# P8 运行与交付加固实施计划

## 目标

让本地交付不只“能启动”，还能够持续运行、发现故障、恢复停滞任务、验证生产配置并完成可回滚恢复演练；不在缺少 SMTP/模型账号时伪造外部服务通过状态。

## 子任务

- [x] 配置门禁：新增生产配置校验库和 `production:doctor`，检查 HTTPS 来源、独立强密钥、数据库角色、迁移、SMTP/通知驱动、目录权限与磁盘空间；输出必须脱敏。
- [x] 后台进程：本地启动器同时管理 API、网页、模拟 API、维护进程和本地通知投递器；任一关键子进程异常退出时整体安全停止。
- [x] 组件状态：`local:status` 显示各组件与 PID/运行状态；API 健康检查区分存活与数据库就绪，不泄露连接信息。
- [x] 通知可靠性：发送任务增加领取时间和租约；进程崩溃留下的 `sending` 任务可恢复，失败指数退避，达到上限进入 `dead` 并生成系统告警。
- [x] 告警与隐私：客户端只接收可操作的告警摘要，不返回错误堆栈、路径、密钥或任务密文；通知状态不返回密文。
- [x] 恢复演练：隔离环境执行停机备份、损坏拒绝、恢复到新库、媒体/密钥校验、旧库保留和回滚配置检查。
- [x] 权限回归：应用角色不能读取通知密文、写维护记录/系统告警或绕过 RLS；独立后台角色/迁移角色的职责写入文档。
- [x] SMTP 验收入口：支持只验证连接与认证、不发送邮件；真实 SMTP 未配置时状态明确为待验收。
- [x] 最终能力清单：逐项列出已完成、本地测试提供商通过、需要外部配置、需要真机和不在当前范围的能力。

## 状态

2026-10-31：本地与测试驱动范围完成，34 个完整回归任务、全新离线安装和正式本地迁移通过。以下项目需外部账号或公网基础设施，保持待验收：

- [ ] 真实 SMTP 连接、实际收件、退信和邮件声誉。
- [ ] 外部监控/告警渠道、多实例共享限流、对象存储与异地灾备。

## 验收标准

1. 一键启动后五个本地组件都在状态输出中，维护至少成功运行一次，验证/重置邮件由本地投递器落入权限受限的 outbox。
2. 陈旧发送任务可重新领取；连续失败进入 dead 并产生一次告警，成功任务有 provider/message-id，普通应用账号看不到密文。
3. `production:doctor` 对默认密钥、HTTP 公网来源、复用密钥、缺失 SMTP 配置和高权限应用账号失败；输出不出现密码/令牌。
4. 完整隔离恢复演练通过，正式业务库不被测试清空或替换。
5. 真实 SMTP、实际模型/OCR、实体手机和公网多实例能力缺失时保留为待验收，不使用“完整生产就绪”结论。
