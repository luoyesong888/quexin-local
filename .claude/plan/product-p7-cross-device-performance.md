# P7 跨端体验与性能实施计划

## 目标

在不改变现有视觉体系的前提下，使鹊信的关键流程具备可重复的 Chromium、Firefox、WebKit、手机视口、键盘与 WCAG 2.2 AA 自动化验收，并为大量本地资料建立明确性能预算。自动化浏览器内核和模拟设备不冒充实体 iPhone、安卓或真实读屏软件。

## 子任务

- [x] 跨浏览器矩阵：Chromium、Firefox、WebKit 的首次进入、八页面导航、创建/编辑、备份恢复与安全胶囊边界通过；增加 iPhone/Pixel 视口及横竖屏回流检查。
- [x] 无障碍基础：增加跳到主要内容链接、路由后的可理解焦点、状态播报和页面地标；原生弹窗验证初始焦点、焦点约束、Esc 与焦点回收。
- [x] WCAG 自动化：接入 axe-core，扫描关键页面与弹窗的 WCAG 2.2 A/AA 规则，不用全局禁用规则掩盖问题。
- [x] 键盘与视觉辅助：验证纯键盘导航、可见焦点、200% 放大、320px 回流、文本间距、减少动态效果和强制色彩模式。
- [x] 软键盘与触控：验证手机编辑器在可视高度缩小时仍能看到当前字段和提交操作；关键触控目标至少 24×24 CSS px。
- [x] 大数据量与长任务：以 1,000 条回忆、500 条计划和 300 篇文字恢复本地备份，建立加载、搜索、切页、保存和导出的本机预算；不阻塞交互，不泄露私人/胶囊正文。
- [x] 备份体验：大备份恢复、刷新持久化、导出和损坏文件拒绝通过，并记录文件体积与耗时。
- [x] 报告与门禁：新增 `test:compat`、`test:a11y`、`test:performance`，并入完整回归；输出自动化证据与真机人工检查清单。

## 状态

2026-10-31：自动化开发和验收完成，31 个完整回归任务通过。以下项目需要外部实体设备，当前保持待验收：

- [ ] 实体 iPhone Safari、中文输入法、主屏幕安装和 VoiceOver。
- [ ] 实体安卓 Chrome、中文输入法、返回键、主屏幕安装和 TalkBack。
- [ ] 真实低端设备、系统级浏览器缩放、弱网与存储不足。

## 验收标准

1. 三个浏览器内核的关键流程全部通过；WebKit 仅表述为 WebKit 自动化，不表述为实体 Safari。
2. axe WCAG 2.2 A/AA 没有未解释的 critical/serious 违规；键盘、焦点和状态播报另有显式测试。
3. 320px、200% 放大、横屏和模拟软键盘没有横向裁切或提交按钮不可达。
4. 大数据集恢复后首次可交互、搜索、页面切换、保存和导出均达到报告中的本机预算，刷新后数量一致。
5. 当前环境无法验证的实体设备、VoiceOver/TalkBack、真实 Safari/安卓 Chrome 和系统后台行为单独列为待验收，不用模拟结果替代。
