# 鹊信本地发布包与 WorkBuddy 部署路线（修订版）

## 已确认的交付边界

- 不部署公网服务器，不配置域名、HTTPS、公网对象存储、多实例或外部监控。
- 暂不做手机真机、PWA 安装、VoiceOver/TalkBack 和浏览器关闭后的手机提醒。
- 最终交付为一个可复制/上传的本地发布包，由后续使用者的 WorkBuddy 在其电脑完成检查、安装、初始化、启动与诊断。
- 首版以 macOS 为目标，因为当前已有 `.command` 启动器、Node.js 22 和 PostgreSQL 17 本地运行链路。Windows/Linux 另行扩展。
- 发布包不内置任何开发者模型、OCR、SMTP 或数据库密钥。没有外部密钥时仍可使用本地检索、人工导入、本地邮件预览及全部核心记录功能。

## 最终交付物

1. `quexin-local-macos-<version>.tar.gz` 本地发布包。
2. SHA-256 校验文件、发布清单、版本号和数据库迁移范围。
3. WorkBuddy 部署入口：检查、安装、初始化、启动、状态、诊断、备份、升级和停止。
4. 面向 WorkBuddy 的 `DEPLOY_WITH_WORKBUDDY.md`，使用确定命令而不是让其猜测项目结构。
5. 可选能力配置模板：模型/OCR/转写/SMTP 均默认关闭或本地替代，密钥只写入使用者本机 `.env.local`。
6. 升级包流程：升级前备份、迁移、健康检查、失败回滚；不覆盖旧数据库。
7. 卸载说明：默认只移除程序，用户数据单独确认，禁止一条命令误删 `.local-data`。
8. 干净 macOS 临时目录和全新本地数据库的最终验收报告。

## 阶段拆分

### L1 发布边界与预检：0.5–1 个工作日

- 固定首版支持环境：macOS、Node.js 22.12+、PostgreSQL 17、Chromium/Chrome/Safari 桌面浏览器。
- 新增 WorkBuddy 预检：CPU 架构、系统版本、Node/npm、PostgreSQL、端口、磁盘、目录权限和依赖可用性。
- 所有输出脱敏，缺少依赖时返回可执行修复建议，不擅自安装系统软件。

验收：在缺 Node、缺 PostgreSQL、端口冲突、磁盘不足和旧数据存在时，分别给出准确提示且不修改数据。

### L2 WorkBuddy 一键部署流程：1–1.5 个工作日

- 新增统一命令，例如 `node scripts/workbuddy-deploy.mjs install|start|status|doctor|backup|stop`。
- `install` 执行锁定依赖安装、数据库初始化、迁移和首次健康检查；重复执行保持幂等。
- WorkBuddy 只需按文档执行固定命令，不需要理解内部五组件实现。

验收：全新目录一条安装流程后可打开 `127.0.0.1:4188`；重复安装不重置资料。

### L3 可分发发布包：1 个工作日

- 新增 `release:bundle`，只收集运行必需的源码、静态资源、迁移、脚本、锁文件和说明。
- 排除 `.local-data`、`.env.local`、测试结果、报告、日志、缓存、备份和开发者隐私资料。
- 生成 manifest、文件 SHA-256、版本、Node/PostgreSQL 要求和打包时间。
- 新增 `release:verify`，在解包后核对数量、摘要、必需文件和禁止文件。

验收：发布包不含数据库、照片、账号、密钥或历史日志；篡改任意文件会校验失败。

### L4 首次使用与可选能力配置：1 个工作日

- 首次启动继续提供空白空间或虚构 Demo，不要求真实邮件/模型才能进入。
- 本地邮件继续由开发邮件箱和本地 outbox 完成验证/重置演示。
- 提供 WorkBuddy 配置命令或安全模板，让使用者选择性填入自己的模型/OCR/转写/SMTP 信息。
- 配置后调用 doctor，只展示服务名和状态，不展示密钥。

验收：零外部密钥可完整使用核心功能；提供合法测试配置时能力状态正确，错误配置不会导致数据丢失。

### L5 升级、备份、回滚与卸载：1–1.5 个工作日

- 升级前自动要求停机备份，记录旧版本、迁移和回滚配置。
- 新包只替换程序文件；数据库迁移成功后才启动新版本，失败时保留旧数据和旧程序包。
- 提供“仅卸载程序”和“用户明确二次确认后删除数据”两条独立路径。

验收：旧版本数据升级后保留；损坏升级包被拒绝；回滚能重新启动旧版本；默认卸载不删除用户数据。

### L6 最终本地交付验收：1–1.5 个工作日

- 在路径含空格的全新临时目录，从发布压缩包开始执行 WorkBuddy 文档。
- 验证安装、首次启动、账号、双人空间、导入、照片、胶囊、备份恢复、停止与再次启动。
- 运行完整 PostgreSQL 回归、发布包校验和本地 doctor。
- 输出最终版本清单、已完成能力、可选外部能力和明确不支持项。

验收：全新 macOS 环境在依赖具备后可由 WorkBuddy 独立完成部署；交付包之外不依赖开发者电脑上的隐藏文件。

## 工期

| 范围 | 预计工期 |
| --- | ---: |
| macOS 本地发布包 + WorkBuddy 部署 | 5–8 个工作日，约 1–2 周 |
| 同时支持 Windows | 额外 4–7 个工作日 |
| 同时把真实模型/OCR/转写接入做质量验收 | 需使用者提供服务账号，额外 2–5 个工作日 |

## 不再作为本轮前置条件

- 公网服务器、域名、HTTPS、S3、异地灾备、20 人在线公测。
- 手机端适配、真机测试、系统推送和原生 App。
- 真实 SMTP 送达；本地开发邮件箱和 outbox 足以支持本地使用。
- 个人微信直连、第三方可信时间、端到端加密和对方已下载副本的远程删除。

## 推荐执行顺序

严格按 L1 → L2 → L3 → L4 → L5 → L6 进行。先保证 WorkBuddy 能可靠安装，再打包；不要先压缩当前开发目录后让 WorkBuddy 猜测如何运行。
