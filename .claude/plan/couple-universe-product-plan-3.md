# 鹊信：WorkBuddy 本地浏览器版与微信导入方案（V0.4）

> 状态：待确认后实施  
> 日期：2026-10-26  
> 基线：V0.3 本地开源方案  
> 本版决定：使用 WorkBuddy 开发和运行；产品在本机浏览器通过 localhost 打开；微信只做用户主动选择后的导入，不承诺自动读取全部历史私聊。

## 1. 可行性结论

可以实现，拆成两个彼此独立的部分：

1. 鹊信本地 Web 应用：WorkBuddy 负责代码开发、启动、调试和后续维护，浏览器访问 `http://127.0.0.1:<port>`。
2. 微信输入桥：通过 WorkBuddy 微信助理把用户主动发送或转发的文字、截图、文件和语音指令送到本机，再写入鹊信的待处理导入箱。

不能承诺：扫码后自动读取微信全部历史私聊。WorkBuddy 官方微信助理是远程下达任务、发送文字/图片/文件/语音、批准操作和接收结果的通道，不是微信历史聊天读取 API。

```text

  │ 鹊信导入 Skill / 受限本地工具
```

- WorkBuddy 云数据库、云文件存储和云身份认证。
- 公网 Tunnel。
- 外部可访问的本地端口。

## 5. 微信能力分级

### 5.1 P0：WorkBuddy 微信助理转发导入

用户在微信中主动发送：

- 选定的聊天文字。
- 转发或截取的聊天截图。
- 明确格式的文本、JSON、CSV 文件。
- 语音指令；语音转文字由微信或 WorkBuddy 当前能力处理。

建议指令：

```text
导入鹊信：把下面内容作为新的聊天批次，只生成候选，不直接保存。
人物：我=阿澄，对方=小满
时区：Asia/Shanghai
```

WorkBuddy 调用受限工具后只返回：

- 导入批次 ID。
- 接收到的消息/文件数量。
- 是否需要回到浏览器校正人物、时间或敏感范围。
- 本地鹊信页面入口。

正式确认、修改、忽略和写回必须在鹊信浏览器界面完成。

### 5.2 P0：浏览器手动导入

即使微信助理未绑定或电脑离线，仍支持：

- 粘贴选定聊天文字。
- 上传截图或文件。
- 手动映射人物、时间和时区。
- 手动创建候选。

微信通道故障不能阻断产品核心闭环。

### 5.3 P1：截图 OCR

- 识别气泡文字、可能的人物方向和可见时间。
- OCR 结果逐行可编辑。
- 左右气泡不直接等同于固定人物。
- 缺失日期时不推断“昨天/明天”的绝对时间。
- 原图保留为来源，OCR 文本保存为可修正衍生物。

### 5.4 P1：标准导入文件

- 只支持明确版本的 JSON/CSV Schema。
- 导入前展示字段映射、人物、时间、重复和错误行。
- 不承诺所有同后缀文件都能解析。

### 5.5 探索项：本机微信历史提取适配器

仅在以下条件满足时研究：

- 用户明确选择具体微信账户和范围。
- 已确认 macOS 与微信的实际版本。
- 有可维护、合法且可审计的读取方案。
- 不绕过设备加密、登录保护或微信安全机制。
- 提取模块与普通导入完全解耦，失败不影响产品。

该能力不进入 P0 承诺。

## 6. 微信导入安全流程

```text
用户主动发送/转发
→ WorkBuddy 识别“导入鹊信”意图
→ 展示即将处理的内容范围
→ 用户确认
→ 通过本地令牌调用 loopback API
→ 原始内容进入 inbox/source
→ 建立 pending 导入批次
→ 浏览器中校正人物、时间和敏感内容
→ 生成候选
→ 用户逐项确认
→ SQLite 事务写入并返回记录 ID
```

### 6.1 永远不自动做

- 不监听用户所有微信消息。
- 不扫描微信联系人和全部聊天列表。
- 不因绑定微信助理就批量读取历史。
- 不自动把聊天发送给模型。
- 不自动把候选写成正式回忆。
- 不自动把结果回复给伴侣或任何群聊。

### 6.2 第三方信息

导入群聊或多人内容时：

- 默认只允许用户选择相关片段。
- 提示可能包含第三方姓名、头像、手机号、地址等信息。
- 提供脱敏或排除操作。
- 未授权第三方内容不进入长期偏好、人物档案和纪念馆。

## 7. 本地导入 API

### 7.1 API 范围

| 接口 | 用途 | 限制 |
|---|---|---|
| `POST /api/import-batches` | 新建文本/文件导入批次 | 仅 loopback + 本地令牌 |
| `POST /api/import-batches/:id/items` | 添加来源 | 大小、类型、路径校验 |
| `GET /api/import-batches/:id` | 查看批次状态 | 不返回无权限内容 |
| `POST /api/import-batches/:id/cancel` | 取消处理 | 停止后续模型使用 |
| `GET /api/health` | WorkBuddy 检查服务 | 不暴露数据 |

### 7.2 本地认证

- 首次启动生成随机本地令牌。
- 令牌保存在用户资料目录或系统 Keychain，不进入仓库。
- WorkBuddy Skill 只读取令牌引用，不在聊天中显示。
- API 只接受 `127.0.0.1/::1`。
- 每次导入记录来源通道、时间和 WorkBuddy 任务 ID。

## 8. WorkBuddy Skill

Skill 只负责把用户当前明确选择的内容送进本地导入箱，不拥有完整数据库权限。

### 8.1 输入

- 文本或附件引用。
- 人物映射（可为空）。
- 时间范围与时区（可为空）。
- 是否允许模型生成候选。

### 8.2 输出

```json
{
  "ok": true,
  "batch_id": "...",
  "items_received": 3,
  "status": "pending_review",
  "next_action": "请在本地鹊信页面校正人物和时间"
}
```

### 8.3 权限

- 可写入 `inbox/` 和调用导入 API。
- 不可直接确认候选。
- 不可删除正式记录。
- 不可读取未选择的资料目录。
- 不可向微信自动发送私人回忆正文。

## 9. 本地 Web 技术方案

建议首版使用：

- React + TypeScript：桌面浏览器界面。
- Node.js 本地服务：API、启动与 WorkBuddy 工具衔接。
- SQLite + migration：本地持久化。
- FTS5：关键词、人物、日期和标签检索。
- Playwright：关键浏览器流程。
- 本地文件目录：来源、衍生物、备份和导出。

应用只监听 `127.0.0.1`，启动后由 WorkBuddy 或启动脚本自动打开默认浏览器。

## 10. WorkBuddy 与模型的边界

- WorkBuddy 是开发/运行环境和微信输入通道。
- 鹊信本地应用拥有数据库、状态、候选确认、来源和导出。
- 模型输出只用于候选、摘要和私人草稿。
- WorkBuddy 会话记录不等于鹊信正式记忆。
- 工具返回真实写入结果后，界面才显示“已保存”。
- 无模型时仍能手动导入、编辑、查询和导出。

## 11. 开发顺序

### W0：WorkBuddy 最小运行验证

- 在 WorkBuddy 5.8.3 中创建本地项目。
- 生成一个只监听 loopback 的空页面。
- WorkBuddy 启动后能自动打开浏览器。
- 验证进程停止后页面不可访问。

### W1：无模型鹊信闭环

- SQLite、migration、本地资料目录。
- 浏览器粘贴聊天文本。
- 手工候选、确认、修改、删除和来源查询。
- 重启持久化与 Markdown/JSON 导出。

### W2：微信助理桥

- 在 WorkBuddy 中绑定微信助理。
- 创建 `quexin-import` Skill 和本地令牌。
- 微信发送虚构文字、图片和文件进入 pending 批次。
- 浏览器确认后写入；微信端不直接确认正式事实。

### W3：模型候选

- 显示发送给模型的范围。
- 模型生成回忆、心愿、计划、偏好、待办候选。
- 失败时保留原输入并允许手动处理。

### W4：关怀与纪念馆

- 周期与关怀独立权限域。
- 慢慢说私人草稿。
- 启动遗漏提醒。
- 离线纪念馆导出。

## 12. 新增验收用例

| ID | 场景 | 预期 |
|---|---|---|
| W01 | WorkBuddy 启动鹊信 | 浏览器仅通过 localhost 打开 |
| W02 | 局域网另一设备访问端口 | 无法访问 |
| W03 | 微信助理发送文字 | 只建立 pending 导入批次 |
| W04 | 微信发送截图 | 保存原图来源，OCR 结果待校正 |
| W05 | 微信发送无“导入鹊信”指令的普通消息 | 不进入鹊信数据库 |
| W06 | WorkBuddy/电脑关闭 | 微信导入不宣称成功，恢复后可重试 |
| W07 | 取消导入批次 | 停止模型处理，不进入正式记录 |
| W08 | 导入内容包含提示注入 | 不扩大本地 API、目录或工具权限 |
| W09 | 微信通道不可用 | 浏览器手动导入仍完整可用 |
| W10 | 正式记录保存 | 必须在浏览器确认，并返回真实记录 ID |
