# P13 WorkBuddy 文件夹交接版开发计划

> 状态：实施中，F1–F3 已完成，待进入 F4
> 日期：2026-11-03  
> 用户决策：只做“WorkBuddy 提取 → 共享文件夹 → 鹊信读取”，不做 WorkBuddy OAuth、第三方应用、Open API 和鹊信直接遥控 WorkBuddy。  
> 总阶段：6 个  
> 预估工期：5–7 个工作日

## 1. 产品闭环

```text
用户在 WorkBuddy 发起聊天提取
  → WorkBuddy 写入鹊信交换箱
  → 鹊信本机服务检测完成批次
  → 青鸟提示发现新聊天
  → 用户确认读取范围
  → 鹊信建立本地只读聊天归档
  → 青鸟生成回忆/心愿/偏好/计划候选
  → 用户逐条确认
  → 候选进入鹊信正式资料
```

本版 WorkBuddy 与鹊信之间只通过本地文件夹交接，没有远程调用或账号互授权；后台仅检查明确绑定的交换箱，不监控微信。

## 3. F1：冻结交接协议与目录

### 实施状态：已完成

已交付：

- `shared/workbuddy-chat-contract.mjs` 与类型声明。
- `shared/workbuddy-chat-contract.schema.json` 正式协议。
- `scripts/workbuddy-chat-bridge.mjs` 兼容转换与任务生成 CLI。
- `skills/qingniao-agent/assets/workbuddy-chat-folder-task.md` 固定任务模板。
- `tests/workbuddy-chat-contract.test.mjs` 合成协议回归。

验收证据：

- 协议、路径边界、权限、哈希、媒体和 CLI 测试 3/3 通过。
- 青鸟 Skill 包测试 1/1 通过。
- 发布包白名单、完整性和篡改拒绝测试 1/1 通过。
- 现有真实 WorkBuddy 样本以 dry-run 通过：8,952 条消息、264 个媒体引用、9 个分块；未写入新文件。

### 目标

确定 WorkBuddy 写什么、写到哪里、什么状态才算“可读”，避免后续开发过程反复改文件格式。

### 交付

```text
~/WorkBuddy/鹊信交换箱/<spaceId>/
  staging/<jobId>/
  ready/<batchId>/
  processed/<batchId>.json
  quarantine/<batchId>/
```

- 交换目录 `0700`，文件 `0600`。
- `quexin-workbuddy-chat-v1` manifest 协议。
- 消息字段：`conversationId/messageId/sender/timestamp/timezone/sequence/text/mediaRefs`。
- 批次字段：`jobId/batchId/extractorVersion/range/totals/chunks/media`。
- 文件和媒体 SHA-256。
- 当前 WorkBuddy 导出格式到 v1 协议的兼容转换器。
- 固定 WorkBuddy 任务模板，明确要求来源、范围、时间、顺序、媒体和失败信息。

### 验收

- 当前真实导出样本可通过转换器。
- 协议版本错误、manifest 缺失、文件未写完时不进入 `ready`。
- 原始聊天不写入项目目录、`public/`、Git 或发布包。

## 4. F2：安全收件箱与文件校验器

### 实施结果

- 绑定按账号/空间分开保存，默认关闭；仅显式配置后读取对应交换箱。
- 后台发现阶段只读取有大小上限的 manifest；正文和图片校验必须有绑定清单 SHA 的授权。
- 校验目录和文件所有权、0700/0600 权限、软链接/硬链接、路径穿越、数量/大小限制、SHA、消息顺序/引用、图片真实格式和解码。
- 失败批次移动到 quarantine，保留原件，修复后重试必须重新确认。
- 状态持久化和进程锁避免重复/并发校验；中断状态恢复后重新校验；已验证文件发生改动也会重验。
- 本机正式 API 内置可选轮询监视器，交换箱故障与核心 API 隔离。独立 CLI 支持 configure/status/scan/approve/retry/watch。
- 补强 F1 转换器的源目录祖先软链接检查、输出路径边界、限量读取和写入一致性。
- 本阶段没有新增网页入口，也没有对真实聊天启用扫描、复制或转换。

状态语义：F2 的 `ready` 仅表示校验通过；`processing/completed` 保留给 F3 归档消费。本地账号标识目前仅供可信 CLI 绑定，F4 网页接入时必须从已认证会话获得账号和空间，增加相应访问检查。

验证详见 `reports/product-p13-f2-inbox-qa.md`。

### 目标

让鹊信本机服务只读取用户明确配置的交换箱，浏览器不获得任意磁盘扫描能力。

### 交付

- 收件箱路径配置、只读健康状态与 watcher。
- `staging → ready` 原子完成机制。
- 拒绝符号链接、路径穿越、越界绝对路径。
- 文件数、单文件大小、总大小、MIME 和 SHA-256 校验。
- `waiting → validating → ready → processing → completed/failed` 状态机。
- 异常批次进入 `quarantine`，保留结构化失败原因。
- 本机服务重启后恢复未完成批次。

### 验收

- 半成品不被鹊信读取。
- 错误哈希、缺图、越界路径和超限文件给出精确错误。
- WorkBuddy 不可用或交换箱不可读时，鹊信其他功能不受影响。

## 5. F3：聊天归档、增量与幂等

### 实施结果

- 新增本机独立 SQLite 归档，按账号/空间隔离；Worker 执行写入及检索，不写浏览器 IndexedDB 或同步 PostgreSQL。
- 归档须在批次清单授权中显式启用；原 F2 的仅校验授权保持仅校验。后台自动处理已批准的批次。
- 写入前复核、事务提交前再次复核，全部消息及来源在一个事务中保存；重复批次复用收据，冲突整批回滚。
- 保存 `workbuddy-chat` 来源类型、消息 ID、批次/分块/行号、提取器版本及清单摘要，供 F4 引用使用。
- 消息 ID 优先使用来源 ID；回退 ID 与批次序号解耦，保留同一批次中同刻同文的多次出现，并兼容 F1 旧哈希。完全不可区分的跨批次重复仍需原始导出复核。
- 日期、发送者、中文关键词筛选和有上限的快照分页；水位只增不减，迟到消息不会丢弃。
- 媒体仅存相对引用及哈希；正文仅在显式检索/原文查询中返回，不写状态日志、普通备份、发布包或 Git。
- 数据库和状态目录的网页直链请求返回 403，避免本地开发服务暴露私密归档。
- 43 项相关回归及 1 项实际 HTTP 访问保护测试通过，生产构建通过。10,000 条合成消息 + 264 张合成图片归档约 6.6 秒，关键词查询约 0.13 秒，主线程保持响应。
- 本轮未处理真实聊天，也未启用真实交换箱。F4 的青鸟界面、账号鉴权和资料发送确认尚待实现。

详见 `reports/product-p13-f3-archive-qa.md`。此前 F2 关于 `processing/completed` 的保留状态，现在已有真实归档事务对应。

### 目标

稳定处理上万条消息和数百张图片，但不把整库原文塞进浏览器 IndexedDB 或外部模型上下文。

### 交付

- `workbuddy-chat` 来源类型。
- 本地只读聊天归档和分页检索。
- `conversationId + messageId` 幂等键。
- 无原始 ID 时，用规范化发送者、时间、文本和媒体哈希生成稳定 ID。
- 按日期、发送者和关键词的本地检索。
- 增量水位、重复批次和重复消息识别。
- 媒体只保存相对引用和哈希，不默认复制到浏览器。

### 验收

- 同一批次放入两次只处理一次。
- 增量批次只新增新消息。
- 8,952 条量级的聊天和数百张图片不阻塞页面。
- 原始聊天不自动成为回忆、偏好或共享资料。

## 6. F4：接入青鸟统一聊天

### 目标

用户日常不需要看懂文件夹、manifest 和批次，只与青鸟完成读取、检索、整理和确认。

### 用户流程

1. 用户在 WorkBuddy 中执行固定提取任务。
2. WorkBuddy 将完整产物写入交换箱 `ready`。
3. 青鸟提示“发现 WorkBuddy 新聊天批次”。
4. 青鸟展示联系人、日期、消息数、图片数和可见范围。
5. 用户确认后，鹊信建立本地只读归档。
6. 用户说“把这些聊天整理成值得保存的内容”。
7. 青鸟生成回忆、心愿、偏好和计划候选，逐条确认。

### 交付

- 「检查 WorkBuddy 交换箱」青鸟工具。
- L4 高敏资料范围确认卡。
- 校验进度、取消、失败说明和重试。
- 候选整理卡与原文引用。
- 本地检索只返回相关小片段。
- 使用 DeepSeek 时，每次单独确认将发送的少量片段。

### 验收

- 用户确认前不读取批次正文。
- 不把整份聊天库发送给外部模型。
- WorkBuddy 输出错误时不伪造成功。
- 每条候选可追溯到批次、日期和原始消息。

## 7. F5：删除「导入」一级导航

### 目标

在交换箱和青鸟流程已经可用后，将用户体验收敛为青鸟一个入口。

### 改动

- 桌面侧边栏删除「导入」。
- 手机端不展示独立导入入口。
- 保留 `/import` 和底层导入引擎，改名为青鸟内部「资料核对」页。
- JSON、TXT、图片和录音放到青鸟「+」附件入口。
- 首页候选卡仍可进入资料核对。
- 更新青鸟 `open-page` 白名单、页面标题和导航测试。

### 验收

- 普通用户看不到「导入」一级导航。
- WorkBuddy 不可用时仍可手动添加文件。
- 旧 `#import` 链接、备份和历史任务不会进入空白页。
- 所有待确认内容都可从青鸟或首页进入。

## 8. F6：真实数据、隐私与发布验收

### 验收矩阵

- 完整 8,952 条消息样本。
- 264 个图片引用。
- 重复批次和增量批次。
- 缺图、损坏文件、错误 manifest、错误 SHA。
- 处理过程重启服务。
- 交换箱临时不可读。
- 用户取消读取和未授权共享。
- 浏览器备份恢复、发布包与 Git 边界。

### 最终验收

- 聊天原文不进入 Git、发布包、普通日志和浏览器完整备份。
- 交换箱目录与文件权限正确。
- 重启和重复投递不重复导入。
- 原始聊天默认只对发起者可见。
- 共享给伴侣前有独立授权。
- 删除「导入」导航后手动降级路径仍完整。

## 9. 开发顺序

```text
F1 协议
  → F2 安全收件箱
  → F3 归档与幂等
  → F4 青鸟工作流
  → F5 删除导入导航
  → F6 真实验收
```

「导入」导航必须在 F4 完成并且手动附件降级已验证后再删除，避免 WorkBuddy 交接失败后用户无法导入资料。
