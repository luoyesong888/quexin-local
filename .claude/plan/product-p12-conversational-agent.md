# P12 青鸟普通对话与连续上下文实施计划

## 目标

修复统一聊天仍把所有问句当作本地资料检索的问题。青鸟需要同时具备普通对话、来源化个人资料问答和动作 Agent 三种底层路径，但用户仍只面对一个输入框。

## 路由

1. 普通对话：问候、能力询问、一般建议和不涉及本地事实的交流；无需本地资料，可调用模型直接回答。
2. 个人资料问答：涉及“我们、第一次、回忆、计划、纪念日”等本地事实；只依据可引用资料回答，没有来源时明确不知道。
3. 操作指令：记住、提醒、安排、写信、处理附件等；进入 Skill 编排和审批。

## 阶段

1. [完成] 增加普通对话输入/输出 Schema 与统一聊天 `conversation` 操作。
2. [完成] 路由器区分普通对话、能力询问与个人资料问答。
3. [完成] 普通对话携带最近有限轮次上下文，不携带本地资料或私密工具结果。
4. [完成] 增加无需模型的真实能力说明，回答“你能做什么”。
5. [完成] Skill 规则补充“先回答，再在必要时提出动作”。
6. [完成] AI、无模型回退、隐私、产品工具、完整回归与发布包全部通过。

## 安全边界

- 普通对话只发送用户本轮文字和最近对话，不自动附加回忆、计划或个人资料。
- 个人资料问题没有来源时不得交给通用模型猜测。
- 模型不得声称已经执行动作；需要动作时继续生成审批卡。
- 对话历史最多发送最近 10 条纯文本用户/青鸟消息，不发送 API Key、附件二进制、审批内部字段或系统日志。

## 验收

- “你现在可以做什么”返回真实能力说明，不再提示没有资料。
- 空白账号可以正常问候和多轮对话。
- “我们第一次去海边是什么时候”在无来源时仍明确不知道。
- 普通对话请求中 `sources` 不存在，且不包含本地记录正文。
- 操作指令和资料问答原有审批与来源边界不回退。
