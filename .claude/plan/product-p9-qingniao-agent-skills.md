# P9 青鸟 Agent 与 Skill 实施计划

## 目标

把现有单次问答升级为本地优先、可暂停、可审批、可追溯的青鸟 Agent。Agent 可按目标选择多个 Skill，但不得绕过资料范围确认、共同空间写入确认或外部行动确认。

## GitHub 调研结论

- Skill 包采用 `agentskills/agentskills` 的开放 `SKILL.md` 目录规范，保留 `references/` 与 `assets/` 渐进加载结构。
- 运行控制借鉴 `langchain-ai/langgraphjs` 的 durable execution / human-in-the-loop 原则：步骤持久化、动作前中断、审批后恢复、每个副作用幂等。
- 当前项目不新增 LangGraph 运行时依赖；用现有 React、IndexedDB、DeepSeek Responses API 与严格 JSON Schema 实现轻量状态机，减少安装体积和隐私面。

## 阶段

1. [完成] Skill 包与目录：创建 `qingniao-agent` Skill，定义六个内置技能、审批等级和动作协议。
2. [完成] Agent 模型协议：增加目标路由、步骤、来源、草稿动作和追问的严格结构化输出。
3. [完成] 本地持久状态：保存 Agent run、轮次、步骤、审批和实际执行结果；备份/恢复与多标签页兼容。
4. [完成] Agent 工作台：在青鸟助手加入 Agent 标签、目标输入、自动发现、图片流水线、计划跟进与关系回顾。
5. [完成] 工具执行：回忆草稿、计划/提醒、日历 ICS、邮件草稿；所有写入和外部跳转先审批。
6. [完成] 验收与发布：结构/权限/失败回退/E2E/可访问性/完整回归和 WorkBuddy 发布包全部通过。

## 内置 Skill

| Skill | 输入 | 草稿输出 | 最低审批 |
| --- | --- | --- | --- |
| `discover-imports` | 新的待确认导入 | 整理建议、回忆草稿 | L1 |
| `image-to-memory-plan` | 用户主动选择的图片与 OCR 文本 | 回忆草稿、计划草稿 | L1/L2 |
| `plan-follow-up` | 待办、日期和完成状态 | 跟进建议、提醒草稿 | L1 |
| `calendar-draft` | 已确认计划草稿 | ICS 日历草稿 | L3，下载前确认 |
| `email-draft` | 用户指定收件目的和资料 | 邮件主题与正文草稿 | L3，打开邮件客户端前确认 |
| `relationship-review` | 用户逐次选择的已确认资料和多轮回答 | 来源化回顾、缺口、下一问 | 只读自动；写入另审 |

## 不变量

- 不主动扫描微信、磁盘、邮箱或系统日历；“自动发现”只检查已经进入鹊信本地资料库的新候选。
- 私人、敏感、已忽略和未选择资料不发送模型。
- Agent 只能提出动作；保存记录、创建计划、下载日历、打开邮件草稿均由用户逐项批准。
- 不自动发送邮件，不直接写第三方日历，不做关系裁决、心理诊断或忠诚度推断。
- 每个 run 记录所选 Skill、来源 ID、步骤状态和工具真实结果，但不记录 API Key。

## 验收标准

- Agent 能根据目标选择一个或多个白名单 Skill，模型不能发明 Skill/工具 ID。
- 图片流程可完成 OCR → Agent 草稿 → 用户审批 → 新建回忆与计划。
- 待确认导入和临近日程能生成建议；没有新内容时不伪造发现。
- 多轮回顾可恢复最近 run，引用只来自发送来源。
- ICS 与邮件动作只生成本机草稿；取消审批不产生任何副作用。
- Agent run 随浏览器备份/恢复，旧备份仍可加载。
- 无模型、未同意、超时或结构错误时明确停止或回退，不假装执行成功。
