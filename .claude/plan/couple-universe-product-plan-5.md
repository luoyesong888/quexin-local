# 鹊信 WorkBuddy 网站应用最终开发方案（V1.0）

> 文档状态：范围冻结，待进入实施  
> 产品形态：WorkBuddy 网站应用  
> 使用方式：本地单人或双人同步可选  
> 主要能力：恋爱记忆、聊天导入、关怀计划、AI 助手、十套主题、鹊巢电子宠物、主题光标、离线导出。

## 0. 最终交付目标

交付一个可以通过 WorkBuddy 发布和访问的网站应用：

- 用户可以不登录，以本地模式使用。
- 用户可以开启同步，分别登录并加入同一个情侣空间。
- 已确认的共同内容可以双人同步。
- 原始聊天、私人草稿和敏感数据默认不上传。
- AI 默认使用 WorkBuddy 网站应用能力，并保留自定义 API、本地模型和关闭 AI 的接口。
- 支持十套完整视觉主题和可配置主题光标。
- 支持共同电子宠物“鹊巢”。
- 支持完整数据导出和离线纪念馆。

## 1. 已冻结的产品决策

### 1.1 品牌与角色

- 产品名称统一为“鹊信”。
- AI 助手名称为“青鸟助手”。
- 电子宠物模块为“鹊巢”。
- 首只宠物为“小鹊”。

### 1.2 运行环境

- 最终形态采用 WorkBuddy 网站应用。
- 前端优先适配桌面浏览器，兼容平板和手机查看。
- 网站应用使用 WorkBuddy 云数据库、身份认证和文件存储，具体能力在 M0 做真实 API 验证。
- 若平台实时能力不足，数据访问层必须允许替换同步实现。

### 1.3 数据模式

- 本地模式：无需账户，使用浏览器本地数据仓库，不同步。
- 双人同步模式：使用账户、情侣空间、云数据库和私有媒体存储。
- 两种模式共用业务组件和领域模型。
- 用户可在设置中开启同步或关闭同步。

### 1.4 AI 模式

- 关闭 AI。
- WorkBuddy AI。
- 自定义模型 API。
- 本地兼容模型端点。

AI 模式与数据同步模式相互独立。

### 2.1 前端技术

- React。
- TypeScript 严格模式。
- Vite 构建。
- CSS Variables 设计令牌。
- IndexedDB/OPFS 作为本地模式数据层。
- Service Worker 负责静态资源与离线壳。
- 可访问组件基础设施。
- Playwright 浏览器端测试。

### 2.2 数据访问原则

所有页面只能调用统一 Repository：

```ts
interface MemoryRepository {
  list(query: MemoryQuery): Promise<MemoryRecord[]>
  get(id: string): Promise<MemoryRecord | null>
  save(input: MemoryInput): Promise<MemoryRecord>
  invalidate(id: string, reason: string): Promise<void>
}
```

Repository 下方根据配置选择 Local 或 Cloud Provider，避免为同步和非同步各写一套页面。

## 3. 用户、账户与情侣空间

### 3.1 本地模式

- 不要求注册。
- 生成本地匿名用户 ID。
- 数据存入 IndexedDB/OPFS。
- 浏览器存储可能被清理，必须持续提示备份。
- 支持完整导出和导入恢复。

### 3.2 双人同步模式

- 邮箱、手机号或 WorkBuddy 支持的认证方式。
- 创建情侣空间。
- 邀请码/邀请链接。
- 一个空间最多两位正式成员。
- 邀请一次性、可撤销、可过期。
- 两位成员分别保留个人偏好与私人区。
- 支持退出、解绑、冻结、导出和删除流程。

### 3.3 开启同步

```text
本地模式
→ 创建账户
→ 创建情侣空间
→ 选择上传范围
→ 展示数据数量和大小
→ 高敏感内容单独确认
→ 上传并生成云端版本
→ 本地保留缓存
→ 邀请另一方
```

### 3.4 关闭同步

提供三种选择：

- 停止后续同步，保留云端数据。
- 下载完整副本后停止同步。
- 下载完整副本并申请删除云端数据。

## 4. 数据可见性

| 范围 | 默认可见方 | 云端策略 |
|---|---|---|
| 我的私密 | 创建者 | 默认本地；用户主动选择后可加密同步 |
| 双方共享 | 两位成员 | 开启同步后上传 |
| 待对方确认 | 发起人和被确认人 | 同步状态，不视为正式共同事实 |
| 秘密惊喜 | 创建者 | 可密封同步，揭晓前不向对方返回正文 |
| 周期详细数据 | 本人 | 默认不上传、不共享 |
| 私人沟通草稿 | 本人 | 默认不上传 |
| 系统审计 | 系统与相关成员 | 不包含完整敏感正文 |

- 计划与计划变更。
- 待办。
- 近期/长期偏好。

- 合并、忽略和确认。

### 5.5 回忆与照片墙

- 图文时间线。
- 照片墙。
- 年/月/人物/地点/标签筛选。
- 原始聊天、照片、语音和视频来源。
- 修改历史和记录版本。
- 心愿、计划、待办关联。
- 隐藏、暂停推荐、失效和删除。
- 那年今日。

- 纪念物收藏。

### 5.6 回忆搜索与问答

### 5.8 心愿、计划与待办

- 心愿清单。

### 5.9 日历与纪念日

## 6. 青鸟助手

### 6.1 能力

- 从聊天生成候选。
- 搜索带来源回忆。
- 整理照片和文字。
- 标出缺失信息。
- 检查偏好冲突和过期。
- 将心愿整理成计划和待办。
- 生成关怀和私人表达草稿。
- 制作回顾和纪念馆草稿。
- 展示处理范围、来源、步骤和错误。

### 6.2 禁止

- 未确认直接写事实。
- 冒充伴侣。
- 自动发消息、下单和预订。
- 关系、心理和医学诊断。
- 使用未授权私人内容。
- 根据聊天量、消费或回复速度评分。

## 7. AI Provider 设计

```ts
interface AIProvider {
  generateCandidates(input: CandidateRequest): Promise<CandidateResult>
  answerWithSources(input: SourceQuery): Promise<SourceAnswer>
  draftPrivateText(input: DraftRequest): Promise<DraftResult>
}
```

### 7.1 WorkBuddy AI

- 网站应用默认 Provider。
- 使用 WorkBuddy 提供的模型能力、积分和权限。
- 鹊信不保存平台内部密钥。
- M0 验证结构化输出、图片输入和调用限制。

### 7.2 自定义 API

- DeepSeek、OpenAI、Kimi、GLM、MiniMax 或兼容接口。
- 密钥保存在用户安全凭据区，不进入业务数据库和同步。
- 调用前显示供应商和发送范围。

### 7.3 本地模型

- 兼容 Ollama/OpenAI 协议端点。
- 由用户自己配置。
- 能力不足时回退模板和手动模式。

## 8. WorkBuddy 微信接入

### 8.1 正式交付

- 微信助理绑定指引。
- 主动发送或转发文字、图片、文件和语音。
- “导入鹊信”指令。
- 创建 pending 导入批次。
- 返回批次 ID 和处理状态。
- 浏览器内完成正式确认。
- 微信入口失败不影响浏览器手动导入。

### 8.2 不承诺

- 扫码自动读取所有历史私聊。
- 持续监听全部消息。
- 扫描联系人和群聊。
- 绕过微信加密和保护。

写操作必须执行服务端身份和空间权限检查，不能只依赖前端隐藏按钮。

## 14. 实时同步与冲突

### 14.1 同步状态

- 本地保存。
- 等待同步。
- 同步中。
- 已同步。
- 同步失败。
- 存在冲突。

### 14.2 同步机制

- 本地 outbox 保存离线操作。
- 恢复网络后按顺序提交。
- 每个写操作带幂等键。
- 服务端返回新版本。
- 实时通道通知另一方。

### 14.3 冲突处理

- 不同字段修改可自动合并。
- 同字段同时修改展示双方版本。
- 删除与编辑冲突时不静默恢复。
- 宠物动作采用事件追加，房间布局采用版本检查。

## 15. 隐私与安全

- 默认最小上传。
- 原始微信聊天默认不进入云端。
- AI 调用前展示供应商和范围。
- 私有媒体使用短期签名 URL。
- 上传校验文件类型、大小和配额。
- 邀请链接一次性、过期和撤销。
- 权限默认拒绝。
- 敏感操作二次确认。
- 所有高风险写操作审计。
- 日志不记录密钥、完整正文和永久媒体 URL。
- 支持完整数据导出和删除请求。
- 提示注入内容不能改变工具权限。
- 周期信息按敏感数据处理。

## 17. 开发里程碑

### M0：平台与架构验证

- 验证 WorkBuddy 网站应用、云数据库、认证、存储和 AI。
- 建立 Provider 接口。
- 建立 CI、代码规范、错误监控和环境隔离。
- 迁移当前 Demo 为正式工程骨架。

退出条件：完成一个真实账号、一个云端记录和一次 AI 结构化输出。

### M1：账户、空间和核心数据

- 本地/同步模式选择。
- 账户、情侣空间、邀请和权限。
- 数据迁移和本地缓存。
- 备份、导出和审计基础。

退出条件：两个账号进入同一空间，第三个账号无法读取。

### M2：导入、候选和记忆

- 文字、图片和标准文件导入。
- 人物时间映射。
- AI 候选。
- 候选确认和正式写入。
- 回忆、照片墙、来源和搜索。
- WorkBuddy 微信主动导入。

退出条件：完整通过“导入→确认→同步→带来源查询→修改失效”。

### M3：计划与关怀

- 偏好、心愿、计划、待办。
- 日历、纪念日和提醒。
- 日常需要、重要事情跟进。
- 周期、慢慢说和相处约定。
- 信件、感谢和时间胶囊。

退出条件：敏感内容默认私人，不自动发送和评分。

### M4：主题与光标

- Theme Engine 与 Layout Presets。
- 十套完整主题。
- 16 款基础光标和场景光标。
- 设置预览、个人/空间主题与可访问性。
- 全主题视觉回归。

退出条件：十套主题全部通过主要页面和尺寸验收。

### M5：鹊巢电子宠物

- 取名、孵化和三阶段成长。
- 基础互动、羽光、装饰和成长日志。
- 双人同步与离线队列。
- 回忆明信片、心愿旅行和首页小组件。
- 十套基础房间皮肤。

退出条件：双方动作 2 秒内同步，关闭 AI 后可完整养成。

### M6：媒体与纪念馆

- OCR、语音转写和视频关键帧。
- 月度/年度回顾。
- 离线纪念馆。
- 完整导出、恢复和长期格式说明。

退出条件：导出包断网可读，媒体和校验清单完整。

### M7：生产硬化与发布

- 权限、安全、性能和可访问性测试。
- 同步冲突、网络异常和降级测试。
- WorkBuddy 正式发布、版本更新与回滚。
- 使用文档、隐私说明、演示数据和源码压缩包。

退出条件：无阻断缺陷、无已知高危安全问题、核心 E2E 全部通过。

### 17.1 开发量级

- 核心可双人使用版本：约 6—8 个单人开发周。
- 包含十套主题、十八款光标、鹊巢和高级创作的完整 V1.0：约 20—24 个单人开发周。
- 十套主题和宠物场景若需要重新制作全部美术资产，应额外预留视觉制作与逐主题验收时间。

该量级用于排期和拆分，不作为固定交付承诺；M0 完成平台验证后再形成精确迭代计划。

## 21. 范围冻结后的变更规则

- 新需求先进入 backlog，不直接插入当前里程碑。
- 涉及数据模型、权限、同步或 AI 范围的变更必须重新评审。
- UI 微调可进入对应主题迭代。
- 宠物新物种、小游戏和复杂 3D 不进入 V1.0。
- 微信全量历史提取保持探索项，不作为发布阻断条件。
