# 双人宇宙：情侣专属数字空间产品方案（V0.1）

> 文档状态：待确认  
> 项目类型：0→1 私密情侣 Web/PWA 产品  
> 方案原则：先做可长期使用的核心体验，再扩展 AI、游戏与外部平台能力。

## 1. 产品概述

### 1.1 产品定位

“双人宇宙”是只属于两个人的私密数字空间。用户可以保存共同回忆、查看恋爱历程与重要日期、写信和制造小惊喜，并能把全部资料导出为可长期保存的离线纪念馆。

它不是公开社交平台，也不是普通网盘。核心差异是：

- 内容以“两个人的关系时间线”为中心组织，而不是按文件夹堆放。
- 进入空间本身具有仪式感和情绪价值。
- 数据默认私密，并支持完整导出，避免回忆被平台锁死。
- AI 仅在双方明确授权后处理私密内容，且每项能力都可单独关闭。

### 1.2 目标用户

- 核心用户：异地或重视纪念感、愿意共同记录生活的情侣。
- 首版使用规模：一个空间固定两位成员；先服务真实的两人场景，不做公开社区。
- 使用设备：手机优先，同时兼容桌面浏览器；可安装为 PWA。

### 1.3 核心价值主张

> 给两个人一个能共同建设、随时回看、长期带走的数字世界。

### 1.4 产品目标与非目标

首版目标：

1. 让创建者在 5 分钟内建好空间并放入第一段回忆。
2. 让伴侣通过一次性邀请安全加入。
3. 让双方持续记录照片、文字、日期和信件。
4. 能生成完整备份，保证数据可迁移、可长期保存。
5. 建立可继续扩展小游戏和 AI 助手的技术底座。

首版不做：

- 不做公开动态、陌生人关注、排行榜或内容推荐。
- 不做微信/QQ 聊天记录自动抓取。
- 不做原生 iOS/Android App，先用响应式 Web + PWA 验证需求。
- 不在 MVP 中实现开放式 AI 聊天、复杂 3D 世界或大量小游戏。
- Cloudflare Tunnel 只用于临时演示，不作为正式生产发布方案。

## 2. 产品范围与优先级

### 2.1 MVP（P0，首个可上线版本）

| 模块 | 核心能力 | 价值 |
|---|---|---|
| 账户与双人空间 | 邮箱/第三方登录、创建空间、一次性邀请、加入/退出、成员状态 | 建立私密边界 |
| 宇宙首页 | 双方昵称、恋爱天数、下个纪念日倒计时、精选回忆、快捷入口 | 每次打开都有情绪回报 |
| 回忆时间线 | 发布/编辑/删除文字、日期、地点和标签；按时间浏览 | 产品主干 |
| 照片与视频 | 多图上传、封面、缩略图、查看器；视频限制与进度提示 | 保存真实素材 |
| 纪念日 | 纪念日增删改、周年循环、倒计时、时区正确计算 | 高频回访理由 |
| 双人信箱 | 草稿、立即发送、定时开启/时间胶囊 | 制造惊喜 |
| 空间装扮 | 主题色、封面、背景音乐开关；提供克制的预设主题 | 个性化与仪式感 |
| 数据与隐私 | 私密访问、导出 ZIP/JSON/Markdown、删除空间、双方敏感操作确认 | 建立长期信任 |
| PWA 与适配 | 手机优先、可安装、基础离线壳、弱网与上传失败恢复 | 接近 App 的体验 |

### 2.2 V1.1（P1，验证留存后）

- 回忆地图：按地点查看共同足迹。
- 年度回忆册：自动按月份排版，可导出 PDF。
- 评论、表情回应、共同编辑状态。
- 每日问答、愿望清单和约会灵感。
- 一个轻量互动玩法，例如“默契问答”；题库可配置。
- Web Push 或邮件提醒，允许双方分别订阅和关闭。

### 2.3 V2（AI 与沉浸体验）

- AI 回忆助手：基于双方授权内容做检索问答、年度总结和回忆卡片。
- AI 约会策划：根据城市、预算和双方偏好生成建议，不擅自发送或预订。
- AI 内容整理：为照片生成候选标题、标签和时间线摘要，必须由用户确认后写入。
- 可视化“记忆星球/博物馆”：先做轻量 2D/伪 3D，再评估 WebGL 3D。
- 可扩展的双人小游戏模块。

### 2.4 V3（长期保存与可选连接）

- 一键生成完全离线的静态纪念馆包，支持 U 盘长期保存。
- 本地优先的桌面封装版本。
- 经双方分别授权后，接入允许的数据源；优先官方导出文件导入，不依赖违规抓取。
- 家庭纪念、婚礼展示等可选模板，但不得破坏情侣私密空间的主定位。

## 3. 关键用户旅程

### 3.1 创建空间

1. 用户登录。
2. 输入双方称呼、恋爱开始日期和时区。
3. 选择一个主题并上传封面。
4. 添加第一条回忆或跳过。
5. 系统生成有时效、一次性使用的邀请链接。
6. 创建者进入宇宙首页，可随时重新生成或撤销邀请。

### 3.2 伴侣加入

1. 伴侣打开邀请链接，先看到空间名称和邀请人，不显示私密内容。
2. 登录或注册后明确确认加入。
3. 邀请令牌立即失效，空间成员变为两人。
4. 双方看到“对方已加入”提示，完成首次共同引导。

### 3.3 记录一段回忆

1. 从首页点击“记录此刻”。
2. 输入文字并选择实际发生日期，可上传照片/视频、地点和标签。
3. 上传显示进度，可取消、重试；草稿不因刷新丢失。
4. 发布后进入时间线，并更新首页精选内容。

### 3.4 制造一次惊喜

1. 用户写信并选择“立即送达”或“指定时间开启”。
2. 时间胶囊在开启前只显示存在，不泄露正文。
3. 到期后对方收到站内提示；若订阅通知，再发送外部提醒。

### 3.5 带走全部回忆

1. 任一成员申请导出，完成二次验证。
2. 系统异步生成包含媒体、结构化数据、Markdown 索引和校验清单的 ZIP。
3. 下载链接短期有效并记录审计日志。
4. 删除空间需要双方确认；若只有一方要求退出，则保留合理的个人数据导出路径。

## 4. 信息架构与页面

### 4.1 一级导航

- 首页：关系总览、倒计时、精选回忆、快捷操作。
- 回忆：时间线、相册、标签/年份筛选。
- 互动：信箱、时间胶囊，后续承载问答和小游戏。
- 我们：双方资料、纪念日、主题、通知和隐私设置。

### 4.2 主要路由建议

```text
/
/login
/onboarding
/invite/:token
/space/:spaceId/home
/space/:spaceId/memories
/space/:spaceId/memories/new
/space/:spaceId/memories/:memoryId
/space/:spaceId/letters
/space/:spaceId/anniversaries
/space/:spaceId/settings
/space/:spaceId/settings/export
```

### 4.3 视觉与交互方向

- 视觉关键词：夜空、微光、星轨、胶片、克制浪漫；避免廉价粉色模板感。
- 首页用“关系天数 + 下一纪念日 + 回忆星轨”形成唯一视觉焦点。
- 动效只服务仪式感：首次进入、信件开启、时间线切换；支持“减少动态效果”。
- 手机端底部四栏导航，桌面端为侧栏；所有核心任务单手可完成。
- 触控目标、颜色对比、键盘操作和屏幕阅读语义按 WCAG 2.2 AA 设计。

## 5. 技术方案

### 5.1 推荐技术栈

| 层级 | 选型 | 说明 |
|---|---|---|
| 前端 | Next.js + TypeScript | SSR/路由/接口一体，生态成熟，适合 PWA |
| UI | Tailwind CSS + 可访问组件库 + Motion 动效库 | 建立主题令牌，减少随意样式 |
| 服务端 | Next.js Server Actions/Route Handlers | MVP 保持单体，业务变复杂后再拆服务 |
| 数据库 | PostgreSQL（推荐 Supabase 托管） | 关系模型清晰，便于行级权限和迁移 |
| 认证 | Supabase Auth 或等价托管认证 | 避免自建密码体系；支持邮箱魔法链接/OAuth |
| 媒体 | 对象存储 + 私有桶 + 短期签名 URL | 原图不可公开直链；生成缩略图 |
| 部署 | Vercel + Supabase（首选简化方案） | 正式域名、HTTPS、预览环境和回滚更直接 |
| 监控 | 错误监控 + 结构化日志 + 可用性探测 | 不在日志中记录正文、令牌和媒体 URL |
| 测试 | 单元/集成测试 + Playwright E2E | 覆盖邀请、权限、上传、导出等关键链路 |

如明确要求全量 Cloudflare，可切换为 Workers/Pages + D1/Postgres + R2，但这属于架构选择，不建议为“学习 Tunnel”牺牲首版交付速度。

### 5.2 系统边界

```text
手机/桌面 PWA
    │ HTTPS
Web 应用与服务端接口
    ├── 认证与双人空间权限
    ├── 回忆/纪念日/信件业务
    ├── 导出与通知任务
    └── AI Provider Adapter（V2 才启用）
          │
          ├── PostgreSQL：结构化数据与权限关系
          ├── 私有对象存储：照片、视频、导出包
          └── 队列/定时任务：提醒、缩略图、导出
```

关键原则：每次读取都以 `space_id + membership` 做授权判断；前端隐藏按钮不能替代后端鉴权。

### 5.3 环境

- Local：本地开发与测试数据。
- Preview：每个合并请求独立预览，不使用真实私密数据。
- Production：独立数据库和存储，迁移可回滚，环境变量由平台保管。

## 6. 核心数据模型

| 实体 | 关键字段 | 约束 |
|---|---|---|
| `profiles` | user_id, display_name, avatar_key, timezone | 用户可修改自己的资料 |
| `spaces` | id, name, start_date, theme, owner_id, status | 一个空间最多两名有效成员 |
| `space_members` | space_id, user_id, role, joined_at, status | 唯一 `(space_id,user_id)` |
| `invitations` | token_hash, space_id, expires_at, used_at, revoked_at | 存哈希，不存明文令牌 |
| `memories` | id, space_id, author_id, title, body, happened_at, location, visibility | 默认空间内可见 |
| `media_assets` | id, space_id, memory_id, object_key, type, size, checksum, status | 私有对象键，不保存公开 URL |
| `anniversaries` | id, space_id, title, date, recurrence, timezone | 服务端统一计算日期规则 |
| `letters` | id, space_id, author_id, recipient_id, body_ciphertext/body, open_at, opened_at | 开启时间由服务端判定 |
| `reactions` | id, target_type, target_id, user_id, emoji | P1 启用 |
| `export_jobs` | id, space_id, requester_id, status, expires_at | 导出链接短期有效 |
| `audit_logs` | id, actor_id, space_id, action, target_type, created_at | 不记录私密正文 |

所有业务表包含 `created_at`、`updated_at`；使用软删除与后台清理期，避免误删后立即不可恢复。

## 7. 隐私、安全与伦理要求

### 7.1 默认安全

- 空间默认不可被搜索引擎索引；分享链接不能越过登录和成员校验。
- 邀请链接一次性、可撤销、短期有效；数据库只保存令牌哈希。
- 媒体使用私有桶和短期签名地址；上传检查 MIME、扩展名、体积和配额。
- 登录、邀请、上传和导出接口做速率限制与异常告警。
- 生产环境启用 HTTPS、安全响应头、CSRF/XSS 防护与依赖扫描。
- EXIF 定位信息默认移除；若用户选择保留地点，作为独立字段保存。

### 7.2 双方知情与同意

- 导入聊天记录、启用 AI 读取共同内容、连接外部平台等能力，必须双方分别确认。
- AI 数据用途、发送给哪个模型、保存多久必须在开关旁清楚说明。
- AI 输出不得伪装成对方本人，也不得自动代表用户发消息或做关系决策。
- 分手/退出场景纳入设计：退出、导出、删除和内容归属必须有明确流程。

### 7.3 备份与恢复

- 数据库自动备份并定期验证恢复流程。
- 导出包包含 `index.html`/Markdown、JSON、媒体文件、文件校验值和版本说明。
- 恢复功能至少支持从本产品导出包重新导入；格式需要版本号。

## 8. 非功能指标

| 项目 | MVP 标准 |
|---|---|
| 性能 | 典型 4G 下首页 LCP ≤ 2.5 秒；首屏不加载原图/视频 |
| 可用性 | 核心页面错误有恢复入口；上传支持重试，草稿本地保存 |
| 兼容性 | 最近两个主要版本的 Safari、Chrome、Edge；iOS/Android 常见尺寸 |
| 可访问性 | 关键流程满足 WCAG 2.2 AA；支持键盘和减少动态效果 |
| 安全性 | 不存在已知高危依赖；关键权限有集成测试 |
| 可观测性 | 错误可定位到请求/任务，但日志不泄漏私密内容 |
| 数据完整性 | 媒体含校验值；导出与恢复经过自动化抽样验证 |

## 9. 产品数据与埋点

只采集改进产品所需的最少数据，不采集回忆正文：

- `space_created`
- `partner_invited`
- `partner_joined`
- `first_memory_published`
- `memory_published`
- `letter_scheduled`
- `anniversary_created`
- `export_requested` / `export_completed`
- `upload_failed`（仅错误类型和文件规格）

首版核心指标：

- 激活率：创建空间后 24 小时内完成“第一条回忆 + 发出邀请”。
- 双人激活率：邀请发出后 7 天内伴侣成功加入。
- 关系空间活跃率：过去 30 天至少新增一条回忆、信件或纪念日的空间比例。
- 内容安全指标：越权访问事件为 0；导出任务成功率 ≥ 99%。

## 10. 开发里程碑

### M0：产品定义与体验原型

- 确认名称、目标用户、MVP 范围和隐私规则。
- 输出移动端关键页面线框图与视觉方向。
- 建立设计令牌、交互状态和异常状态清单。

退出条件：关键流程无阻断；用户确认范围与视觉方向。

### M1：工程底座与双人空间

- 初始化项目、代码规范、环境配置、数据库迁移与 CI。
- 完成认证、空间、邀请和成员权限。
- 接入错误监控与基础审计日志。

退出条件：两位测试用户只能访问自己的空间，邀请不可复用。

### M2：核心内容能力

- 完成回忆时间线、媒体上传、纪念日和首页聚合。
- 完成草稿、上传重试、缩略图和基础 PWA。

退出条件：端到端完成“创建空间→邀请→共同发布→浏览回忆”。

### M3：情绪价值与长期保存

- 完成信箱/时间胶囊、主题装扮和动效。
- 完成导出、删除/退出流程、隐私说明。

退出条件：导出包可在离线状态打开，数据与媒体完整。

### M4：发布准备

- 权限、安全、性能、可访问性和跨设备测试。
- 生产部署、域名、备份、监控、回滚和运营说明。
- 用真实但非敏感的种子空间做灰度验证。

退出条件：所有 P0 验收通过，没有阻断级缺陷。

单人全职开发的合理量级是 3–5 周完成可用 MVP；若素材处理、精细动效或第三方登录较多，需要额外缓冲。该估算在 M0 交互稿确认后再细化。

## 11. 测试策略与验收标准

### 11.1 测试分层

- 单元测试：日期/时区、邀请状态机、权限函数、文件校验、导出清单。
- 集成测试：数据库行级权限、成员上限、签名 URL、定时开启、删除恢复。
- E2E：创建、邀请、加入、发布、查看、写信、导出全链路。
- 手工探索：弱网、重复点击、超大文件、过期邀请、跨账号越权、手机旋转。

### 11.2 MVP 验收清单

- [ ] 创建者能在 5 分钟内完成空间创建和第一条回忆。
- [ ] 邀请链接过期、撤销或使用后均不能再次加入。
- [ ] 第三方用户即使猜到 ID 也无法读取空间或媒体。
- [ ] 两位成员均可新增和浏览回忆，编辑/删除规则清晰可预测。
- [ ] 纪念日跨时区、闰年和周年计算结果正确。
- [ ] 图片上传失败可重试；页面刷新后文字草稿仍在。
- [ ] 时间胶囊到期前正文无法从客户端或接口读取。
- [ ] 用户可导出全部数据与媒体，离线索引可打开。
- [ ] 手机端核心流程无横向溢出，键盘和读屏可操作。
- [ ] 生产日志、埋点和错误平台不包含正文、邀请令牌或私有媒体链接。
- [ ] 数据库迁移、部署和回滚均有可重复命令。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 一开始做 3D、AI、游戏导致主线失焦 | 延期且核心记录体验不可用 | 强制按 P0/P1/P2 阶段门禁推进 |
| 私密内容越权或分享链接泄漏 | 严重信任与安全事故 | 服务端权限、私有存储、自动化越权测试 |
| 视频成本快速上涨 | 存储与流量不可控 | 首版限制格式/时长/配额，展示前压缩与转码 |
| 情侣关系变化后的数据纠纷 | 删除或归属争议 | 上线前定义退出、导出、冻结和双方确认规则 |
| AI 处理私密信息引发顾虑 | 用户不敢使用 | 默认关闭、单项授权、供应商透明、可撤销与删除 |
| 过度动效影响性能和可访问性 | 老设备卡顿、眩晕 | 分层加载、减少动态模式、性能预算 |
| 依赖临时 Tunnel 对外发布 | 链接不稳定且难运维 | 正式域名 + 托管部署 + HTTPS + 监控 |

## 13. 开始开发前需要用户确认的决策

这些问题不阻塞本方案形成，但会影响 M0 设计：

1. 产品只是你们两个人使用，还是未来允许其他情侣各自创建空间？
2. 首版必须包含哪些素材：照片、短视频、语音，还是三者都要？
3. 希望走“高级克制的星空”还是“可爱治愈的手账”视觉方向？
4. 登录偏好是邮箱验证码、微信扫码，还是先用一个空间口令？
5. 是否接受首版使用托管服务，还是必须能完全本地部署？
6. 是否将“离线 U 盘纪念馆”列为首版必做，而不是 V3？

## 14. 后续执行顺序

用户确认本方案后：

1. 将已确认决策回写为 V0.2，并冻结 MVP 范围。
2. 先产出信息架构、低保真线框和视觉方案，不直接堆页面代码。
3. 建立工程底座、数据库迁移、权限模型和自动化测试。
4. 按 M1→M4 实施，每个里程碑都提供可运行版本与验收记录。
5. MVP 稳定后再决定 AI、小游戏、外部平台连接和沉浸式博物馆的投入顺序。
