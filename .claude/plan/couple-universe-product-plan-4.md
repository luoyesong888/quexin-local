# 鹊信「鹊巢」双人电子宠物功能方案（V0.5）

> 状态：待确认  
> 产品环境：WorkBuddy 网站应用、双人同步、十套 UI 主题  
> 功能原则：共同养成、回忆驱动、无断签惩罚、无关系评分、无宠物死亡。

## 1. 功能定位

模块名称建议为：

> 鹊巢 · 一起养大的记忆伙伴

首只宠物为原创角色“小鹊”。

- 青鸟助手负责搜索、整理、解释和建议。
- 小鹊负责陪伴、共同养成、回忆唤起和轻互动。
- 小鹊不代表双方感情质量，也不评价任何一方的表现。

## 2. 核心循环

```text
确认一段共同回忆
→ 获得少量羽光
→ 一起照顾小鹊或布置鹊巢
→ 小鹊成长或带回回忆明信片
→ 发起一个可跳过的共同小活动
→ 活动完成后沉淀为新的共同回忆
```

目标是连接“记录→行动→回忆→重新唤起”，而不是制造每日签到压力。

## 3. 启用方式

电子宠物是可选模块：

```text
设置
└── 鹊巢与电子宠物
    ├── 开启电子宠物
    ├── 仅本机养成
    ├── 双人同步养成
    ├── 首页显示小组件
    ├── 通知频率
    ├── 回忆推荐范围
    ├── 减少动态效果
    └── 完全隐藏宠物入口
```

关闭后不删除成长数据，但停止宠物通知和首页展示。

## 4. 成长阶段

| 阶段 | 形态 | 解锁条件 | 解锁内容 |
|---|---|---|---|
| 巢中灵卵 | 带羽纹的小蛋 | 创建情侣空间并共同取名 | 基础鹊巢 |
| 初羽小鹊 | 刚孵化的小鸟 | 完成首次共同互动 | 抚摸、喂食、睡觉 |
| 探索小鹊 | 能在房间活动 | 积累多类型共同记录 | 回忆卡、基础装扮 |
| 同行青羽 | 能外出带回纪念物 | 完成心愿、计划和关怀事项 | 出行、纪念物、主题房间 |
| 守忆灵鹊 | 成熟的记忆守护者 | 长期积累多类型共同经历 | 年度故事和纪念馆入口 |

成长只前进、不倒退。长期不用时进入“安静休息”，不会生病、死亡或责怪用户。

## 5. 状态设计

不设置爱意值、默契度、情侣等级或关系健康分。

宠物只显示三个非评判性即时状态：

- 元气：当前是否愿意玩耍。
- 好奇：是否想探索回忆或心愿。
- 安心：是否想在鹊巢里休息。

这些状态只决定动画和互动文案，不代表关系质量。

正确文案：

```text
小鹊今天很安静，正窝在窗边休息。
```

禁止文案：

```text
你们三天没有来看它，它很伤心。
```

## 6. 基础互动

### 6.1 日常动作

- 抚摸。
- 喂食。
- 轻声呼唤。
- 陪它休息。
- 梳理羽毛。
- 在房间活动。
- 拍一张纪念照。
- 查看今日小动作。

每天无需全部完成，没有连续签到。

### 6.2 双人动作

- 一起取名。
- 一方选择食物，另一方确认。
- 双方分别抚摸后触发特殊动作。
- 共同布置房间。
- 共同选择外出目标。
- 一人留下照顾动作，另一人上线后看到。
- 双方完成一个小问题后解锁纪念物。

### 6.3 后续合作玩法

- 一起拼回忆照片。
- 共同选择纪念馆展品。
- 为小鹊整理行囊。
- 双方各选一件家具组成新房间。
- 不计分、不排名的合作小游戏。

## 7. 羽光与道具

虚拟奖励称为“羽光”。羽光只用于兑换装饰、服装、相框和房间物品，不影响核心功能。

### 7.1 羽光来源

| 行为 | 奖励原则 |
|---|---|
| 确认共同回忆 | 少量，每日设上限 |
| 完成共同心愿 | 较多 |
| 完成共同计划 | 根据计划规模 |
| 留下具体感谢 | 少量 |
| 双方完成轻互动 | 少量 |
| 完成重要事情的关怀跟进 | 少量 |
| 生成年度纪念馆 | 解锁纪念物，不重复刷取 |

### 7.2 不奖励

- 大量导入原始聊天。
- 记录周期。
- 发生冲突。
- 增加聊天次数。
- 连续签到。
- 上传敏感内容。

首版没有付费货币、抽卡、概率开箱、广告奖励或付费成长加速。

## 8. 与现有功能结合

### 8.1 回忆明信片

小鹊从已确认共同回忆中带回明信片：

```text
小鹊在旧相册里找到一张照片：
2024 年 8 月 3 日，你们第一次一起看海。
```

必须显示原始来源，并允许隐藏单条或暂停某段时间的回忆推荐。

### 8.2 心愿旅行

```text
一起去海边
→ 小鹊准备行囊
→ 双方确定时间
→ 完成计划
→ 解锁贝壳纪念物
→ 新照片进入回忆馆
```

### 8.3 羽笺

一句具体感谢可以变成鹊巢里的“羽笺”，但不增加爱意分数。

### 8.4 关怀

只有当事人明确分享“想安静”“想被听见”等需要时，小鹊才显示中性提示。

不根据聊天语气、周期或冲突自动推断。

### 8.5 时间胶囊

小鹊可以保管一封密封信，在指定日期衔回来。未到开启时间不能读取。

### 8.6 年度回顾

- 小鹊成长记录。
- 共同完成的心愿。
- 收集的纪念物。
- 带回的回忆卡。
- 年度房间快照。

## 9. 页面结构

### 9.1 首页小组件

- 小鹊当前动作。
- 最近带回的回忆卡。
- 一次可选轻互动。
- 另一方最近的照顾记录。
- 进入鹊巢入口。

首页小组件可完全隐藏。

### 9.2 独立页面“鹊巢”

```text
鹊巢
├── 宠物与房间
├── 互动按钮
├── 今日小事
├── 回忆明信片
├── 成长记录
├── 衣柜
├── 家具与装饰
├── 纪念物收藏
└── 设置
```

## 10. 十套主题房间

宠物本体共用一套角色骨骼和状态，主题只更换房间、光效和道具皮肤。

| 主题 | 鹊巢表现 |
|---|---|
| 纸上东方 | 宣纸鹊巢、植物线描、木制小桌 |
| 极简墨印 | 黑白几何房间、红色印章玩具 |
| 矿物敦煌 | 矿物壁画洞窟、赭石坐垫、金色挂饰 |
| 未来星图 | 太空舱、星轨窗景、能量羽毛 |
| 新东方编辑 | 高饱和杂志工作室和彩色积木 |
| 胶片档案 | 暗房、胶卷架和老相机 |
| 玉石透光 | 翡翠花园、玉石水池和柔光灯 |
| 江南留白 | 白墙小院、竹影和水边石台 |
| 馆藏目录 | 典藏展柜、编号标签和档案室 |
| 柔光关系杂志 | 奶油色客厅、咖啡桌和花瓶 |

切换主题不会改变成长、道具数量和宠物状态。

## 11. 双人同步

宠物属于 `couple_space`，两个人共同拥有。

同步内容：

- 宠物名称与物种。
- 成长阶段。
- 当前动作。
- 羽光余额。
- 房间装扮。
- 道具库存。
- 回忆卡。
- 成长事件。
- 双方照顾动作。

技术规则：

- 服务端是最终权威。
- 每次互动使用幂等 ID。
- 一方操作后实时通知另一方。
- 离线操作进入本地队列。
- 两人同时改房间时使用版本号和冲突提示。
- 明确显示动作来自哪一位成员。

关闭同步时，宠物可以本地单机运行。本地模式切到同步模式时，由用户决定是否迁移现有成长记录，不自动合并两只宠物。

## 12. AI 边界

成长、奖励、状态和同步均由确定性代码计算，不交给 AI。

AI 只用于：

- 名字建议。
- 简短宠物日记。
- 回忆明信片文案。
- 基于已确认心愿的活动建议。
- 纪念馆章节说明。
- 主题房间描述。

AI 不得：

- 冒充伴侣。
- 判断关系好坏。
- 根据互动频率判断爱意。
- 使用未分享的私人草稿、周期或冲突内容。
- 编造共同经历。
- 用宠物制造内疚。

关闭 AI 后使用预设模板，电子宠物仍可完整运行。

## 13. 数据模型

### `couple_pets`

- `id`, `space_id`, `name`, `species`, `growth_stage`, `created_at`, `hatched_at`。

### `pet_state`

- `pet_id`, `energy_state`, `curiosity_state`, `comfort_state`, `current_animation`, `version`, `updated_at`。

### `pet_action_events`

- `id`, `pet_id`, `actor_id`, `action_type`, `idempotency_key`, `reward_amount`, `created_at`。

### `pet_growth_events`

- `id`, `pet_id`, `from_stage`, `to_stage`, `reason`, `created_at`。

### `pet_inventory`

- `pet_id`, `item_id`, `quantity`, `acquired_from`。

### `pet_room_layout`

- `pet_id`, `theme_id`, `placed_items`, `version`。

### `pet_postcards`

- `id`, `pet_id`, `memory_id`, `text`, `source_refs`, `hidden_at`, `created_at`。

### `pet_missions`

- `id`, `space_id`, `mission_type`, `target_record_id`, `status`, `expires_at`。

任务到期未完成不会扣分或伤害宠物。

## 14. 动画方案

### 首版

使用分层 SVG、CSS 与 Web Animations：

- 呼吸待机。
- 眨眼。
- 跳跃。
- 进食。
- 抚摸反馈。
- 睡觉。
- 带回回忆卡。
- 成长庆祝。

优点是体积小、可换色、容易适配十套主题，并支持减少动态效果。

### 后续

需要更细腻骨骼和状态时可评估 Rive 状态机。首版不使用 3D。

- 一个物种“小鹊”。

- 三个成长阶段。
- 抚摸、喂食和休息。

## 16. 验收标准

- [ ] 两人首次创建宠物不超过 3 分钟。
- [ ] 一方操作后，另一方在正常网络下 2 秒内看到。
- [ ] 重复提交不会重复获得羽光。
- [ ] 离线操作恢复后不丢失。
- [ ] 长期未使用不会死亡、退化或责怪用户。
- [ ] 关闭 AI 后养成功能正常。
- [ ] 宠物不能读取未授权私人资料。
- [ ] 回忆明信片能打开原始来源。
- [ ] 十套主题切换不丢宠物状态和道具。
- [ ] 支持减少动态效果。
- [ ] 关闭宠物后停止宠物通知。
- [ ] 周期、冲突和私人草稿不会产生奖励或状态变化。

## 17. 风险与处理

| 风险 | 处理 |
|---|---|
| 宠物喧宾夺主 | 模块可关闭，首页只显示小组件 |
| 用户觉得幼稚 | 美术保持克制成熟，不做幼儿化音效 |
| 形成打卡压力 | 无连续签到、断签惩罚和宠物死亡 |
| 变成关系评分 | 无爱意值、默契值和排行榜 |
| 为奖励大量导入聊天 | 原始导入不奖励，确认后的有效行动设上限 |
| 泄露私人内容 | 只访问双方共享且已确认资料 |
| 同步冲突 | 服务端版本、幂等事件和实时同步 |
| 十套主题工作量大 | 复用宠物骨骼，只更换房间和皮肤 |
| AI 编造 | 来源约束、模板降级、允许关闭 AI |
| 运营成本失控 | 首版一个物种、有限动作和纯装饰经济 |

## 18. 最重要的原则

> 小鹊应当让两个人更愿意留下真实生活，而不是让两个人为了喂养小鹊而制造虚假活跃。
