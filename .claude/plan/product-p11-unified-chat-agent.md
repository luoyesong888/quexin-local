# P11 青鸟统一聊天式个人智能体方案

## 目标

取消青鸟内部“为你整理 / Agent / 来源 / 记录”四个分页，以及“直接指令 / 图片工作流 / 多轮回顾 / 使用已有资料”等模式按钮。青鸟只保留一个连续聊天流和一个统一输入框；用户只描述要做什么，系统自动完成意图识别、Skill 选择、资料检索、规划和工具路由。

本轮只取消青鸟内部页面。主应用的回忆、计划、关怀、鹊巢、创作和设置页面继续保留，作为结构化数据的浏览、编辑和兜底入口。

## 最终界面

```text
┌──────────────────────────────┐
│ 青鸟助手      模型状态 · 更多 │
├──────────────────────────────┤
│                              │
│ 青鸟欢迎语 / 最近待办         │
│                              │
│ 用户：每周六提醒我们一起散步   │
│                              │
│ 青鸟：我准备创建周期计划。     │
│ ┌──────────────────────────┐ │
│ │ 周期计划草稿             │ │
│ │ 每周六 18:00 · 提前 1 小时│ │
│ │ [确认] [修改] [拒绝]      │ │
│ └──────────────────────────┘ │
│                              │
│ ✓ 已加入本机计划             │
│                              │
├──────────────────────────────┤
│ ＋  输入想让青鸟做的事…   →   │
└──────────────────────────────┘
```

只保留三个视觉区域：

1. 顶部：青鸟身份、模型状态、历史/设置入口和关闭按钮。
2. 中间：用户消息、青鸟回复、资料范围、审批卡、引用和真实工具结果组成的连续消息流。
3. 底部：附件按钮、统一输入框、发送/停止按钮。

## 旧入口迁移

| 当前入口 | 统一聊天中的去向 |
| --- | --- |
| 为你整理 | 空状态建议、青鸟主动生成的“发现新内容”消息 |
| Agent | 整个聊天框本身就是 Agent，不再单列 |
| 来源 | 回答下方“引用 3 条 · 查看”与资料范围卡 |
| 记录 | 工具结果与系统事件进入消息流；完整轨迹放“更多 → 运行详情”抽屉 |
| 图片→回忆→计划 | 用户点击“＋”选图片后自动路由 |
| 多轮关系回顾 | 直接输入“回顾一下最近的变化” |
| 使用已有资料 | Agent 自动检索；发送前在消息流确认资料范围 |
| Skill 目录 | 主界面隐藏，仅在设置或运行详情中查看 |

## 统一交互

### 直接指令

用户指令本身是第一方来源，不要求已有数据：

```text
用户：记住她不吃香菜。
青鸟：我准备保存为“偏好”草稿。
      [确认保存] [修改] [拒绝]
```

### 使用已有资料

Agent 自动搜索，调用外部模型前插入紧凑范围卡：

```text
本次准备使用 3 条本地资料
· 把日落装进口袋
· 第一次成功的晚餐
· 一起走过的山路
[继续] [调整范围] [只用本地检索]
```

### 写入与外部动作

- 创建回忆、偏好、计划、关怀或创作：在对话中显示字段并逐项确认。
- 修改共享资料：显示字段差异与双方可见范围后确认。
- 日历、邮件：显示渠道、实际内容和“不会自动发送”说明后确认。
- 删除、批量导入等高风险动作：继续使用密码或二次确认。

### 附件

底部“＋”只表示输入媒介，不进入模式页：

- 图片/聊天截图；
- TXT、JSON、CSV、HTML；
- 录音（仅转写服务可用时）；
- 微信聊天导入（仅能力门禁通过后出现）。

图片流程自动变为“读取 → OCR → 判断内容 → 生成聊天内草稿 → 逐项审批”。

## Agent 流程

```text
用户消息或附件
→ 意图识别
→ 选择最少必要 Skill
→ 判断是否需要已有资料
→ 必要时生成资料范围确认卡
→ 模型/本地规则执行
→ 生成动作审批卡
→ 用户确认、修改或拒绝
→ 工具执行
→ 返回真实结果与引用
```

权限等级保持不变：本地只读可直接完成；外部模型读取资料需范围确认；本机写入需动作审批；外部渠道需立即审批；高风险操作需二次验证。

## 消息与运行协议

```ts
type AssistantMessage =
  | UserTextMessage
  | UserAttachmentMessage
  | AssistantTextMessage
  | SourceScopeMessage
  | ActionProposalMessage
  | ToolResultMessage
  | CitationBundleMessage
  | SystemStatusMessage
  | ErrorRecoveryMessage
```

运行状态：

```text
queued → routing → awaiting_source_approval → running
       → awaiting_action_approval → executing → completed
       → failed / cancelled
```

流式事件：`run.started`、`routing.selected`、`source_scope.ready`、`model.delta`、`proposal.ready`、`approval.required`、`tool.started/completed/failed`、`run.completed`。界面只显示简短执行说明，不展示隐藏推理过程。

## 技术方案

### 前端

- 用 `AssistantConversation` 替换当前 `Assistant` 四个 Tab 和 `AgentWorkspace` 模式选择器。
- 复用现有回忆、计划、关怀、创作、ICS 和邮件工具执行函数，改由内联消息卡触发。
- 手机端保持全屏对话；桌面继续使用右侧青鸟栏。
- 空状态只显示 3—5 条可点击指令示例，发送第一条消息后消失。

### 服务端

- 新增统一 `POST /v1/assistant/chat` 流式入口。
- 普通问答、直接指令、多 Skill 编排、附件识别、多轮回顾都走统一路由。
- 旧 `/assistant/answer`、`/assistant/agent`、OCR/转写接口暂时保留并作为兼容适配器，稳定后再移除。

### 本地数据

- 增加主线程、消息、审批和工具结果结构；现有 `agentRuns` 继续作为执行审计。
- 旧 `agentRuns` 转换成历史运行消息；旧备份没有聊天数据时自动创建空主线程。
- 新 JSON 备份包含线程、消息、审批和工具结果。

## 微信能力门禁

状态：`unavailable → adapter_present → unverified → verified → enabled`。

只有同时满足真实 WorkBuddy 提取适配器、明确授权、发送者/时间/顺序/来源行号保留、代表样本验收、错误率和失败回退、隐私说明与撤销方式，才注册 `wechat-chat-import`。

门禁未通过时：附件菜单不显示微信入口；Skill 不进入白名单；服务端拒绝伪造 ID；示例聊天、截图 OCR 和演示开关不算真实接入。

## 开发阶段

1. [完成] 统一聊天外壳：移除四个 Tab，建立单一消息流与输入框。
2. [完成] 意图路由兼容层：统一本地问答、模型问答和十个 Skill。
3. [完成] 内联资料确认与审批：范围卡、可编辑动作卡、拒绝与失败恢复。
4. [完成] 附件与外部动作：图片/文件/OCR/录音、ICS 和邮件草稿进入同一消息流。
5. [完成] 历史迁移与微信门禁：旧 run 转消息、运行详情抽屉、能力注册表。
6. [完成] 验收与发布：AI、权限、幂等、备份、WCAG、手机/桌面、完整回归与 WorkBuddy 包全部通过。

## 验收标准

- 青鸟界面不存在功能 Tab 或模式选择按钮。
- 空白账号通过唯一输入框即可创建偏好、计划、习惯、关怀和创作草稿。
- 问答、回顾、图片和文件全部从同一个输入框发起。
- 资料发送范围可在对话中查看和调整。
- 每个写入或外部动作独立审批，拒绝后没有副作用。
- 工具失败显示真实状态，引用从回答内部打开。
- 刷新、备份和恢复后会话、审批和结果仍存在。
- 重复提交不会重复创建记录或计划。
- 微信门禁关闭时，界面和模型均不能使用微信 Skill。
- 手机软键盘打开后输入框和确认按钮仍可见。
- 旧回忆、计划、宠物、双人同步和备份保持兼容。

## 边界

- 青鸟不会在应用关闭后持续监听或自主操作系统。
- 不自动发送邮件、直接写第三方日历或发布内容。
- 不扫描微信、邮箱、磁盘和系统相册。
- 不进行关系裁决、心理诊断或忠诚度评分。
- 一个聊天框是交互统一，不代表取消权限、来源、审批和审计；这些机制改为按需内联展示。
