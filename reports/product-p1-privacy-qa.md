# 完整产品 P1：离线同步隐私保护

日期：2026-10-30。本阶段处理“当前尚未发送的队列是否仍允许上传”，不是完整的远端撤回或资料抹除。

## 实现

- 将记录、来源日程、私人草稿和胶囊的共享规则放到 `shared/sync-policy.mjs`，供页面和生成的 Service Worker 共用。助手的可引用范围也复用同一基础规则。
- 排队内容发送前与当前可共享资料的完整正文比较，不只依赖旧队列状态。改私人、改为待确认、删除、使用私人照片或来源已不共享的日程，均不继续发送原队列中的正文。
- 正文有更新时，前台生成新命令替换旧正文；相同内容保持原幂等编号。后台遇到过时内容先剔除，由页面后续重新整理，不擅自复用可能已提交的旧命令编号。
- 前台同步重新读取当前账号已保存的资料，并再次确认当前登录身份；定时回调不再仅使用挂载时捕获的旧资料对象。
- Worker 发送前读取对应账号 IndexedDB。没有资料库或读取失败时暂停，而不是盲发队列。页面与 Worker 使用同名 Web Lock；不支持锁时 Worker 不主动发送，交回页面处理。
- 拉取远端记录或删除标记时保留本机非共享副本，不把私人副本覆盖回公开版本或一并删掉。
- 服务端返回的非共享标记转换为本机敏感标记，并记录远端私有状态；不把服务端原本私有的记录误识别为待撤回的共享记录。私有信件也不进入发送范围。
- 已不共享内容的旧冲突从队列移除；点击过时冲突按钮也再次检查当前共享范围。正常冲突仍保留原本机版本，供用户明确比较后选择。
- 编辑器提示区分“停止后续排队发送”和“此前已经共享的照片、导出副本仍需处理”。

## 验收范围

下表所列检查均已通过。原有网页回归首次发现离线鉴权失败没有进入重试计数，已修复并单独重跑冲突流程；另外三条同轮已通过。UI 和 Worker 测试使用独立端口与内存服务，未改动服务端数据库实现。

| 检查 | 覆盖 |
| --- | --- |
| `npm run test:privacy` | 9 条：前台旧队列改私人/删除，远端删除标记保留私人本机副本，服务端私有记录不重分享/误删，关联日程、待确认、私人照片、私有信件、草稿、胶囊、更新正文、幂等和冲突筛选 |
| PWA 用例 | 4 条：正常后台提交、关闭页面后阻止私人旧正文、关闭页面后阻止已删除旧正文、账号资料库缺失时暂停 |
| 旧网页回归 | 离线重试和退避、冲突双版本、多标签提交、照片编辑、数据包与删除流程 |
| 双账号 | 两账号共同资料/宠物及账号隔离 |
| 导入与助手 | 9 条原文追溯、候选确认和私人范围回归 |
| 构建 | TypeScript、Vite、生成的 Worker |

固定复测入口为 `npm run test:privacy`、`npm run test:pwa`；`test:full` 已纳入隐私专项。原始运行结果位于 `test-results/privacy/`、`test-results/pwa/`、`test-results/import/`、`test-results/couple/` 和 `test-results/e2e/`。

后台测试特意在资料改私人/删除后重新放回旧队列，再关闭页面，由 Worker 从真实 IndexedDB 读取最新状态。这验证了发送端拦截，而不是仅验证界面已删掉队列。所有测试使用新建会话和内存 API，没有修改现有业务库或调用外部服务。

## 尚未解决的边界（P2）

- 已经发出的网络请求不能按“尚未发送队列”处理；已接受但应答丢失的提交需要后续拉取与撤回确认。
- 当前删除标记不等于服务端旧正文、共享媒体和历史导出包已不可访问。P2 要补齐各自权限、清理和状态验收。
- 伴侣已下载/另存的文件、截图和离线副本不能保证远程抹除。
- 不把本轮 Chromium Worker 的主动触发测试称为手机操作系统后台调度验收。
