# 完整产品 P8：运行与交付加固

日期：2026-10-31。P8 的本地运行、任务可靠性、权限、配置门禁、备份恢复和全新安装已通过；真实 SMTP、公网多实例和外部监控平台尚未配置，因此不使用“公网生产全部就绪”的结论。

## 已实现

- 本地启动器统一托管五个组件：网页、本机账号 API、模拟 API、后台维护、通知投递。`local:status` 显示组件名称、PID 和运行状态；关键子进程异常退出时整体安全停止。
- `/health` 现在实际查询数据库；数据库不可用时返回未就绪，而不是只报告 Node 进程存活。
- 后台维护随本地服务启动并定时运行，清理过期导出、删除到期空间、陈旧媒体、过期会话和令牌；部分或完全失败写入持久告警。
- 通知任务增加领取时间、最近尝试时间和租约。进程崩溃留下的 `sending` 任务可恢复；失败使用指数退避，第五次失败进入 `dead`，并幂等生成一条系统告警。
- 通知本地/JSON 文件权限为 600，目录为 700；默认本地驱动不会访问外部网络。SMTP 驱动可在启动时调用 `verify()`，只验证连接与认证，不发送邮件。
- 应用数据库角色改为列级最小权限：可以读取维护/告警/通知摘要和入队，但不能读取通知密文、告警/维护内部详情，也不能写维护记录、告警或投递状态。
- API 不再向浏览器返回维护/告警内部 `details`；通知状态使用严格 Schema，不含密文、IV 或认证标签。
- 新增 `local:doctor` 和 `production:doctor`：检查来源协议、数据库连接/角色、迁移、独立密钥、通知驱动、SMTP 配置、目录权限、磁盘和模型配置，输出连接串与密钥均脱敏。
- 本地媒体、导出、通知 outbox 与运行目录统一收紧为当前系统用户可访问。
- 全新项目副本可以在离线 npm 缓存中安装锁定依赖、构建、初始化新 PostgreSQL、启动五组件并停止。
