# 本地发布包 L5：升级、回滚与安全卸载

日期：2026-11-01。L5 已完成。升级、回滚和卸载只允许在带有效 `release-manifest.json` 的发布包目录执行，开发目录会被拒绝。

## 已实现

- `upgrade --package <新版本.tar.gz>`：只验证包并展示版本与步骤，不修改资料。
- `upgrade ... --yes`：验证新包及三个 sidecar、停机、服务端数据备份、旧程序发布快照、程序替换、`npm ci`、数据库迁移、五组件健康检查。
- 新包版本必须高于当前版本；同版本仅能显式 `--allow-same-version`，避免误覆盖。
- 损坏的归档、SHA、包内/包外 manifest、路径或文件摘要在停机前被拒绝。
- 如果程序替换或依赖安装失败，自动恢复旧程序。
- 如果数据库迁移开始后失败，自动恢复旧程序，并从升级前备份恢复到新数据库后切换配置；原数据库保留。
- 成功升级记录当前/旧版本、程序快照和数据备份，权限 600。
- `rollback --yes`：先备份当前数据和当前程序，再回滚程序；默认不回退用户升级后新增的数据。
- 回滚自身失败时尝试恢复回滚前程序和原运行状态。
- `uninstall --yes`：最终数据备份后，把 manifest 管理的程序、依赖、构建产物和 `.env.local` 移入 macOS 废纸篓；`.local-data` 保留在原位置。
- 可选配置在卸载前另存到数据目录的 600 权限文件。
- 原目录写入“鹊信数据保留说明”，记录数据、最终备份和可恢复程序位置。
- `purge-data` 是独立操作，必须同时提供 `--yes` 和完整确认语“永久删除鹊信本地资料”；数据仍移入废纸篓，不直接 `rm`。
- 程序移动支持同磁盘原子 rename 和跨磁盘复制后精确移除，不使用宽泛递归目标。

## 真实隔离验收

测试在路径含空格的临时目录创建三个校验发布版本和独立 PostgreSQL：

1. 安装 v0.1.0，注册测试账号。
2. 篡改归档，升级在停机前因 SHA 不匹配被拒绝，旧服务继续运行。
3. 升级到包含故意错误 SQL 迁移的 v0.1.1，验证旧程序和升级前数据库自动恢复，账号仍可登录。
4. 成功升级到 v0.1.2，程序标记、数据库和五组件正常，账号保留。
5. 程序回滚到 v0.1.0，升级后数据不被主动回退，账号仍可登录。
6. 默认卸载后程序进入测试废纸篓，`.local-data` 和最终备份保留。
7. 从废纸篓中的程序执行独立 purge-data，使用完整确认语后数据移入可恢复数据废纸篓。

专项测试：1/1 通过，约 44 秒。测试临时副本使用自己的离线 npm 依赖，不修改开发项目依赖。
