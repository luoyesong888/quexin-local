# 鹊信正式网页版 · 第一阶段进度

更新日期：2026-10-28

> 2026-10-30：本文件保留历史实现记录。后续阶段顺序与验收范围统一以 [本地收尾计划](local-release-plan.md) 为准；历史“已完成”条目不代表产品全部交付。

## 已完成

- 保留桌面与手机双端交互，构建和 PWA 离线壳正常。
- 新建统一 `QuexinRepository` 接口和 `IndexedDbRepository` 实现。
- 将记录、计划、信件/手记、日志和设置拆分到独立 IndexedDB object store。
- 所有数据通过一个原子事务保存，避免部分模块成功、部分模块失败。
- 资料库包含本地匿名 ID、修订版本和最近保存时间。
- 首次加载自动迁移旧版 `quexin-interactive-demo-v1` 数据，暂不删除旧副本。
- IndexedDB 不可用时回退到旧版兼容存储，并在界面提示导出备份。
- 新用户先创建空白空间；虚构示例改为主动选择。
- 系统页和资料状态弹窗显示真实数据库状态。
- JSON 备份与旧版备份结构继续兼容。
- 普通更新改为实体级 patch：只写入发生变化的记录、计划、文字或设置，不再清空并重写整份资料。
- 使用 BroadcastChannel 通知同源标签页，并在收到更高修订版本后载入最新数据。
- 同一浏览器多个标签页修改不同实体时，事务会保留彼此的变更。
- 回忆、计划和信件编辑携带实体版本；旧草稿不会静默覆盖新版本。
- 冲突发生时提供“载入最新”和“保留此页版本”两条显式处理路径，覆盖操作需要二次确认。
- 已定义登录、情侣空间、邀请、成员、可见范围、增量同步、媒体上传和稳定错误码的云端 Transport 契约。
- 已实现只监听 `127.0.0.1` 的本地模拟 API，并在设置页提供双人同步实验室。
- 模拟服务支持会话、创建空间、一次性邀请码、撤销/过期、最多两位成员、幂等命令、游标拉取、私人记录隔离和版本冲突。
- 已新增正式 API：邮箱/密码注册登录、HttpOnly Cookie 会话、Origin 检查、登录限流和稳定错误结构。
- 已新增 PostgreSQL 迁移、连接池适配器、事务同步、行级权限策略和私有媒体元数据表。
- 已安装并启动本机 PostgreSQL 17.11，完成真实迁移、受限角色、RLS、事务和备份恢复测试。
- 设置页已增加“正式账号”模式，可使用邮箱、密码和 HttpOnly Cookie 创建及恢复情侣空间；原快速模拟仍保留。
- 正式账号已增加邮箱验证门槛、单次密码重置令牌和登录设备查看/撤销。
- 本地开发邮件箱只允许回环地址访问；生产环境默认不返回验证令牌。
- 正式账号已增加后台自动增量提交/拉取、15 秒变化检查、在线/可见状态恢复和手动重试；同步游标不再因本端提交跳过伴侣事件。
- 已增加受保护的本机媒体通道：10MB 上限、SHA-256 校验、JPEG/PNG/WebP 解码、方向纠正、WebP 重编码、缩略图及“双方可见/仅自己”权限。
- 浏览器既有稳定字符串实体 ID 已与 PostgreSQL 同步表兼容，避免样例资料因 UUID 限制产生 500。
- 同步元数据已从 `sessionStorage` 迁入独立 IndexedDB；队列、失败次数、游标和冲突快照在刷新/浏览器重启后保留。
- API 离线时可从本机缓存恢复账号和空间摘要；正式会话 Cookie 不会写入缓存，恢复联网后仍由服务端重新校验。
- 冲突中心同时展示本机和云端标题/正文，可选择“采用云端”或“保留本机并按最新 revision 重试”。
- 安全媒体可从回忆编辑器直接上传并绑定 `record`；替换、取消临时上传、移除或删除自有媒体时执行受权限保护的清理。
- 离线队列加入 2 秒起步、最高 5 分钟的指数退避；自动同步只发送到期命令，手动立即同步可绕过等待。
- 队列上限为 500 个实体变更，设置页可展开查看命令类型、尝试次数、失败原因和下次重试时间。
- 正式 API 新增空间同步状态与 owner 媒体清理接口；清理操作验证非 owner 403、重复执行幂等。
- 新增隔离端口的 Playwright 浏览器 E2E，自动复现此前手工完成的离线刷新与 revision 冲突链路。
- 本地变化发现已从设置页提升到 App 全局 hook；用户在回忆/计划/创作页修改后直接关闭，也会先写入持久化队列。
- 生产 Service Worker 新增 `quexin-sync` Background Sync，能在没有页面的情况下读取队列、提交命令、保存 revision/冲突并广播结果。
- 多标签使用同一 Web Lock 串行执行“入队/前台同步”，并通过 BroadcastChannel 重新载入工作区；服务端 commandId 继续兜底幂等。
- 队列诊断支持下载 JSON；尝试达到 5 次或等待超过 24 小时会显示长期失败提醒。
- 正式账号可生成 24 小时有效的 `.json.gz` 数据包，包含当前用户有权读取的实体和媒体副本；伴侣无法导出 owner 私人资料。
- 空间创建者可预约 7 天后删除并撤销；立即永久删除要求完整口令，并级联清除同步数据、成员关系、媒体和导出任务，本浏览器资料不受影响。
- 所有 Modal 通过 `aria-labelledby` 获得可访问名称；该问题由删除流程 E2E 首次发现并修复。
- 新增独立维护进程与第 8 次迁移：过期导出、陈旧上传、到期空间、过期会话/令牌自动清理，每次结果写入只读维护历史。
- 设置页展示最近维护时间、状态和各类清理计数；正式全栈脚本会同时启动维护进程。
- 新增加密通知队列与 SMTP/Webhook/本机投递器；验证和重置令牌不再只存在进程内开发邮箱。
- SMTP 成功回执保存 provider、Message-ID、accepted/rejected；失败指数重试，5 次后进入 dead。
- 安全审计推动 Nodemailer 升级到 10.3.1、Sharp 升级到 0.35.5，最终审计为 0 漏洞。
- 第 9 次迁移增加持久化系统告警：维护部分失败/完全失败分别记录 warning/critical，设置页展示未解决告警。

## 当前边界

这是可在单机运行的正式服务底座：账号、PostgreSQL、双人邀请、自动同步和私有媒体已经接入本机实现。尚未接入公网域名、真实邮件服务、S3 对象存储、多实例共享限流、微信和真实 AI。

## 下一阶段

1. 将本机媒体目录替换为 S3 兼容私有对象存储，并增加病毒扫描、孤儿文件回收与媒体引用关系。
2. 为持久化告警增加加密投递队列与 SMTP/Webhook 适配器，并接入验证邮件和密码重置。
3. 接入真实邮件服务并增加邮箱发送队列、退信处理与监控告警。
