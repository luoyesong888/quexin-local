## 最终交付

- 根目录新增“初始化鹊信.command”“启动鹊信.command”“停止鹊信.command”“检查鹊信.command”。命令行使用 `local:init/start/stop/status`。
- 启动器检查依赖、端口、数据库迁移与应用角色，直接管理网页/API 子进程和控制 socket。重复启动返回现有地址；其他程序占用端口时拒绝启动，不杀进程；只在归属进程已不存在且端口空闲时清理遗留锁。
- 新安装在项目资料目录创建独立 PostgreSQL，随机生成账号凭据和通知密钥，以受限角色运行 API。当前电脑接入原数据库，不替换既有数据；停止鹊信保留系统共享 PostgreSQL。
- `local:backup` 在网页/API 停止后备份数据库、媒体、导出文件、模拟数据和通知密钥，生成文件摘要。`local:restore` 校验后恢复到新数据库和新媒体目录，成功才切换配置，保留原库和恢复前配置。
- 浏览器完整 JSON 在空白浏览器中恢复后，记录、计划、私人草稿、宠物和主题一致。JSON 与服务端备份作用不同，说明已明确区分。
- 修复异步保存队列：每个写入实际执行时与本页上一个已提交快照比较；旧保存完成后不再覆盖更新的 React 状态。数据库事务仍校验其他标签页冲突，现有跨标签页回归通过。
- 手机单人前端预览明确关闭 Vite 的 API 代理；避免默认继承开发服务器代理。该模式不提供账号或双人同步。

## 启动器与备份恢复实测

`npm run test:local-runtime` 在新建临时数据目录和独立 PostgreSQL 实测通过：

1. 初始化、启动、重复启动、停止、重复停止。
2. 旧进程不存在的运行锁恢复；端口被另一个测试 TCP 服务占用时拒绝启动，该服务仍然存活。
3. 注册账号后重启服务，仍可用原密码登录。
4. 运行中备份被拒绝；停机备份生成 dump、媒体与密钥清单，关键文件为 0600。
5. 篡改 dump 后恢复被拒绝，当前配置保持不变。
6. 修改原数据库与媒体后，从备份恢复到新库；恢复后账号名称、媒体副本和密钥与备份一致，原数据库仍保留修改后的内容。

记录：[交付检查](local-delivery-qa/delivery-checks.json)。测试只删除自己创建的临时目录。
