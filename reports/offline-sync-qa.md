# 鹊信离线队列与冲突中心验收

更新日期：2026-10-29

## 覆盖范围

- 正式账号和情侣空间摘要的离线恢复（不缓存 Cookie 或密码）。
- 命令先写入 IndexedDB，再请求正式 API。
- API 停止、页面刷新、API 恢复后的队列连续性。
- 同一实体发生 expectedRevision 冲突后的双版本展示与人工选择。
- 安全媒体与回忆 ID 关联、权限读取和 owner 幂等删除。

## 浏览器验收

1. 正式账号创建空间并完成初次自动同步，离线队列为 0。
2. 伴侣把 `memory-cafe` 更新为 revision 2。
3. 停止 4193 API，在回忆页保存不同的本机版本。
4. 打开设置页：从本机缓存恢复账号与空间，显示“离线队列 1 项”。
5. 刷新页面且保持 API 停止：队列仍为 1 项。
6. 恢复 API 并立即同步：冲突中心同时显示本机标题/正文和伴侣云端标题/正文。
7. 选择“保留本机并重试”：队列归零，PostgreSQL 中该实体更新为 revision 3，标题与本机版本一致。

## API 回归

同一套 9 组 Playwright + Zod 契约测试在 MemoryStore 与 PostgreSQL 17.11 上通过。媒体用例额外验证：关联字段、错误摘要、内容类型、共享/私人/空间外权限、非 owner 删除、owner 删除、删除后读取 404、重复删除幂等。

## 自动化状态

上述核心链路现已固化为 `tests/e2e/offline-sync.spec.ts`：使用隔离的内存正式 API 和 Vite 端口，自动路由中断模拟断网，不依赖固定等待。另有手机、双标签和正式数据生命周期用例。当前结果为 4/4 通过。
